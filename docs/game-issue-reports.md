# 玩家問題回報

設定頁的「回報問題」可提交問題類型與 5～3000 字說明。煉器錯誤彈窗另有「回報管理員」，會預填錯誤標題與診斷資訊；仍由玩家按送出才儲存。

管理頁新增「玩家問題回報」，按「載入／重新整理」取得最新 20 筆，可載入更早回報、查看診斷、填寫備註，以及標記待處理、處理中、已解決。沒有輪詢、登入載入或背景上傳。

`POST /api/game-issues` 使用主專案身分驗證，玩家名稱由伺服器取得；請求 ID 與玩家 UID 決定同一筆回報，逾時後重試不重複新增。交易同時檢查每小時 5 筆、每日 20 筆限制，存在 `gameIssueLimits/{uid}` 的最近一天時間陣列中。

`POST /api/admin/game-issues` 每次核對資料庫中的管理員權限，才可分頁讀取或更新 `gameIssueReports`。一般玩家不能使用瀏覽器資料 API 讀取此集合。回報只接受目前頁面、版本、視窗尺寸、瀏覽器與有上限的診斷字串，遮蔽常見憑證格式，不上傳整份玩家資料。

D1 的 `0005_game_issue_reports.sql` 提供回報時間索引，隨既有 migrations 流程套用。索引只影響回報集合，不增加其他遊戲資料的索引寫入。尚未套用時功能仍可使用，但回報數量增長後的排序讀取量較高。
