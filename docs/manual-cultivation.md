# 體力分支：功法修煉

適用：`stamina-battle`。此功能只替換修煉頁面的入口與玩法，不刪除已有的修為、金丹、元神或舊裝備持有資料。

## 玩家流程

1. 點選底部「修煉」進入功法閣；原本的修煉場景、金丹及元嬰分頁不再顯示，也不主動重新渲染。
2. 選擇劍修或體修。首次選擇免費習得該派一本入門功法；若已達煉氣境（修為 ≥ 1），自動裝備第一招。凡人境可先取得功法，但升至煉氣後才能裝備及施放。切換流派不清空已有功法或熟練度，也不重複取得免費功法。
3. 完成問道試煉 PvE 關卡（必須正常擊敗靈獸、至少答對一題、並成功結算）後，若仍有未收錄功法，30% 機率得到一本未收錄功法。連續三次合格通關未掉落時，下一次必掉；同派書籍優先權為 70%，且仍有機會取得另一派。
4. 每本功法固定三個技能。可在修煉頁消耗靈石直接升一級（每補 1 EXP 消耗 2 靈石，升至 Lv. 10 為止）。打怪累積的 EXP 可抵扣升級費用；修士境界門檻照常檢查。使用該功法技能 **最後一擊擊殺** PvE 靈獸才增加熟練 EXP。獎勵依靈獸的境界（由當場試煉關卡決定）分為 20–430 EXP，越高境界越高。功法從 Lv. 1 開始，升級需求為 `40 + 20 × (目前等級 - 1)` EXP；Lv. 5、Lv. 10 分別滿足第二、三招的**功法等級條件**，仍須達到各招指定的修士境界。普攻、金丹攻擊與 PvP 擊殺不提供功法經驗。
5. 已解鎖的招式可以個別消耗 20／40／60／80 靈石升至 Lv. 2／3／4／5。傷害招式每級提高 10% 基礎傷害，蓄勢每級少消耗 1 點體力。各本功法的同名招式各自記錄等級。
6. 可跨功法、跨劍修與體修自由裝備至多三種**不同且已解鎖**的技能。空裝備欄合法。同名共用招式只能占一個技能欄，可切換所屬功法；擊殺熟練度計入裝備時選定的功法。玩家可命名並儲存三組配置，各組最多三招；舊裝備自動帶入配置一，其餘預設為空。一鍵套用不花費資源。戰鬥與配對期間無法切換或修改使用中的配置，未使用的配置仍可編輯；結束戰鬥或收法離場後即可切換。收起畫面保留戰鬥進度，不算離場。重新進入未完成戰鬥時保留開始時的技能與等級快照。
7. PvE 左下圓盤負責答題充能。右下圓盤選擇「攻擊」後，外環顯示最多三招已裝備技能。點選招式後在地圖上選攻擊目標，切回「移動」會收起招式。未裝備功法技能時，攻擊外環顯示普通攻擊。PvP 在操作區直接列出已裝備技能，沒有裝備時才顯示普通攻擊。金丹技能從所有體力戰棋戰鬥停用。普通攻擊與功法技能預設每回合共用兩次出手、10 點體力上限及技能冷卻。蓄勢可將自己接下來兩回合的出手上限提高為三次。

**所有功法第一招消耗 2 體力**。流風劍訣保留既有熟練度與裝備欄。原青霄劍典的熟練度與裝備欄自動沿用至八方劍典。御劍真訣與伏虎擒拿訣透過試煉掉落取得。玄嶽鍛體訣與龍象真身訣沿用既有熟練度與裝備欄位。每級所需 EXP 遞增 20 點：Lv. 1→2 需 40、Lv. 2→3 需 60、Lv. 3→4 需 80、Lv. 4→5 需 100；Lv. 5 累積 280 EXP、Lv. 10 累積 1080 EXP。

藏經閣只展示玩家已取得的功法。最新體力分支保留由伺服器提供的功法等級、當級 EXP 與招式解鎖條件，並加入「主展示區 → 戰場配置 → 藏經閣收藏卡冊」三部分；招式射程、體力、倍率與 EXP 公式仍由 `public/cultivation/manual-rules.js` 定義。

### 修煉頁視覺與互動（2026-11-17）

- **主展示區：** 放大玩家選中的已取得功法封面、目前熟練度與三招路線；切換展示功法只改變前端視覺焦點，不會修改流派、已裝備技能或戰場配置。
- **戰場配置：** 三組配置各有三個招式欄位。點選欄位可挑選已解鎖且符合境界的招式；已裝備的招式可交換欄位，相同 `moveId` 不可重複。查看未使用的配置不會自動套用；修改使用中的配置仍需通過伺服器的戰鬥狀態檢查。
- **藏經閣：** 卡冊以現有功法封面、等級、EXP、已領悟招數、三招圖片與下一招條件呈現。預設「全部功法」，可切換「劍修」或「體修」篩選；**未取得功法不出現**。選取卡片會同步主展示，點開詳情仍可升級功法、強化招式及裝備技能。
- **穩定性：** 前端沿用 DOM 局部對帳更新，不應為切換配置或升級而重建未變更的封面與招式圖片。降低動態效果設定需受到尊重；遊戲實際數值仍以後端回傳資料為準。
- **突破演出（第四階段）：** 只在伺服器回應確認功法等級提高、技能升級、實際解鎖技能或新功法入藏後，顯示獨立、可關閉的成果視窗。劍修青藍、體修金橙；招式／功法使用原本繪圖素材與既有 `spirit-pulse`、`grand-reveal` 音效，遵循使用者音效設定。符合 `prefers-reduced-motion` 的裝置停用動畫；可點「繼續修煉」、按 Esc 或等待短時間自動關閉。
- **演出觸發邏輯：** 在 `public/cultivation/manual-celebration.js` 比較兩份伺服器功法狀態，不以「按下升級按鈕」推測成功。初次載入不播放；相同資料重複同步不播放；即使達到 Lv. 5 / Lv. 10，**修士境界不足時不能顯示已領悟**；入門功法與 PvE 掉落以不同文案區分。
- **修煉熟練度整合介面（第九階段）：** 主展示頁的「功法氣象」獨立欄位已移除，不再將熟練度與等級分成兩張重複卡片。以單一「修煉熟練度」卡顯示功法等級 `Lv. n / 10`、當級 EXP（或滿級訊息）、修行狀態徽章，以及簡短的階段敘述；滿級時「圓滿」徽章緊靠「功法已達最高等級」左側。大型功法封面角標不再重複顯示階段名稱。
- **靈脈熟練度條：** 同一張熟練度卡內有一條連續的 Lv.1–10 靈脈線，使用伺服器 `level` 及當級 `progress` 插值填滿，不改動原本 EXP／升級規則；其中 Lv.1、Lv.5、Lv.10 以大小略有不同、**圓形凸起且數字置中**的氣穴節點標記，其他等級只保留小刻痕。已達成節點亮起，Lv.10 圓滿時最後一節點有金色高亮，尊重減少動態效果。Lv.5/10 僅是功法等級門檻，**修士境界不足時仍不代表技能已解鎖**。無需另加一條重複的成長刻度。
- **功法的永久視覺成長：** 底層仍根據伺服器功法 `Lv.1–4` 初息、`Lv.5–7` 凝紋、`Lv.8–9` 盛氣、`Lv.10` 圓滿，調整主展示法陣、氣場與收藏卡視覺；僅是外觀，不增加戰力或修改技能資料。
- **動效與穩定性：** 只有高等級主展示法陣可緩慢旋轉，收藏卡片不做持續動畫。啟用 `prefers-reduced-motion` 時停止所有新增的旋轉與閃動。保留原功法圖片的 DOM 節點與三組戰場配置，不因視覺階段改變而重新給予功法、增加 EXP 或影響戰場。
- **戰鬥結算功法 EXP（第六階段）：** PvE 戰鬥結束並且伺服器已將玩家加入 `rewarded` 後，結算視窗依當前玩家的 `manualExp`、舊戰場 `manualKills × EXP_PER_KILL` 顯示本場各本功法累積 EXP；只認得既有功法目錄，不讀取其他玩家的資料。沒有功法 EXP 時顯示明確的空紀錄，不編造獎勵；PvP 不顯示此區。
- **成長進度確認：** 結算視窗再用原有 `GET /api/tactical/manuals` 唯讀同步已結算的功法等級、當級 EXP 進度、距下級／下一招門檻剩餘 EXP，並區分修士境界尚未達成的招式。此讀取失敗不影響已結算戰場，會提供重試或前往功法閣的入口。同一場結算不會因重複渲染發送多次同步請求；新帳號或新戰場不能沿用舊快取。
- **視覺表現與限制：** 劍修青藍、體修金橙的結算卡，短暫顯示本場 EXP 與熟練度進度條動效；系統設定減少動態效果時自動停用。此功能只回顧戰場伺服器已記錄的經驗，**不會重新發獎、額外升級、覆寫功法或更改試煉獎勵**。接續下一關／前往功法閣的原按鈕全部保留。
- **戰鬥中即時 EXP 回饋（第七階段）：** 在同一場 PvE 戰鬥的兩份伺服器狀態之間，依 `manualExp` 的每本功法增量及舊戰場 `manualKills × EXP_PER_KILL` 顯示青藍／金橙小型浮動提示（`public/cultivation/tactical-manual-xp-feedback.js`）。提示只佔戰場頂端中央，不攔截滑鼠與觸控操作，短暫顯示後自動收起，最多列出前三本有 EXP 變化的功法與其餘本數。動畫尊重減少動態效果設定，音效使用玩家既有的開關與音量系統。
- **避免虛假回饋：** 初次載入、不同房間、PvP、舊版快照、同資料重送、其他玩家的紀錄及不認識的功法 ID 均不觸發。只閱讀伺服器已確認的房間經驗帳本，不額外發放經驗，也不改變通關、戰鬥、裝備、功法解鎖或實際的結算流程。戰鬥中新增 EXP 與伺服器永久保存的功法等級需明確區分，後者仍以戰後的 `GET /api/tactical/manuals` 與修煉頁同步結果為準。
- **接近突破的持續回饋（第八階段）：** 修煉頁依伺服器已確認的功法 `totalExp` 與 `totalExpForLevel` 計算 Lv.5、Lv.10 下一招等級門檻的**階段進度**。門檻進度達 75% 顯示「靈氣漸滿」、達 90% 顯示「突破在即」，主展示熟練度條與下一招節點法陣加強外圍光暈；藏經閣卡牌同步顯示接近突破標記。**節點內仍保持灰階上鎖**，直到伺服器真正回傳 `unlocked=true`；若等級達標但修士境界不足，改顯示「境界待突破」，不宣稱技能已領悟。
- **戰場預感（唯讀試算）：** 現有即時 EXP 浮窗可在功法接近 Lv.5 或 Lv.10 時加上一條精簡的門檻進度。以戰鬥中擷取的已確認功法快照為基礎，**僅計入該快照之後、同一房間增加的 EXP**，並明示「本場僅為試算，正式 EXP 與領悟以伺服器結算為準」。玩家換房、換帳號或無法取得可信的基準快照，就不顯示戰鬥門檻試算。無附加獎勵、推播或新的升級計算。
- **動效與驗證：** 只有「突破在即」時的熟練度光效輕微呼吸；遵守 `prefers-reduced-motion`，畫面不阻擋戰場操控與手機觸控。新增 `tests/manual-anticipation.test.cjs`，並擴充 `scripts/test-manual-training-browser.cjs` 驗證接近門檻及境界阻擋情形。
- **驗證：** `tests/manual-training-hero.test.cjs`、`tests/manual-training-loadout.test.cjs`、`tests/manual-training-library.test.cjs`、`tests/manual-training-celebration.test.cjs`、`tests/manual-training-growth.test.cjs`、`tests/manual-anticipation.test.cjs`、`tests/tactical-manual-recap.test.cjs`、`tests/tactical-manual-xp-feedback.test.cjs`，以及 `scripts/test-manual-training-browser.cjs`、`scripts/test-tactical-browser.cjs`。

| 招式 | 體力 | 判定 |
| --- | ---: | --- |
| 流風斬 | 2 | 選一個正向，攻擊前方直線三格。 |
| 突進橫斬 | 4 | 選直線四格內可通行的落點，沿路遇到角色或障礙即無法通過。抵達後連斬前方一排三格，命中兩次，每次造成 140% 攻擊力的基礎傷害（Lv.5 為每次 196%）；顯示數字採實際戰場攻擊力與每擊倍率，不改變原本傷害。 |
| 遠線破擊 | 4 | 劍氣沿正向延伸至障礙或地圖邊界，沿途命中各一次。存活的敵人從最遠的開始推至可落腳的最後一格，受其他角色或障礙阻擋時提前停下。 |
| 召劍 | 2 | 首次在自身直線三格內的空地召劍，飛劍留到本場戰鬥結束。再次施放時從飛劍所在格直線移動最多四格，穿過的敵人各受一次傷害。召喚和移動各占一次出手，可同回合連用兩次。 |
| 交叉劍斬 | 4 | 選三格內可見的中心，四條斜向各延伸兩格。中心最多兩段，完整命中合計 1.6 倍攻擊。 |
| 八方合劍 | 6 | 選四格內可見的中心，正向各三格、斜向各兩格。中心最多八段，完整命中合計 2.4 倍攻擊。 |

## 技能境界門檻

技能需要同時滿足 **功法 Lv. 1／5／10** 與個別的 **修士境界**，才能裝備及施放。

| 功法 | 第一招（Lv. 1） | 第二招（Lv. 5） | 第三招（Lv. 10） |
| --- | --- | --- | --- |
| 流風劍訣、玄嶽鍛體訣 | 煉氣（修為 1） | 築基（修為 6） | 金丹（修為 28） |
| 御劍真訣 | 築基（修為 6） | 築基（修為 6） | 金丹（修為 28） |
| 八方劍典、龍象真身訣、伏虎擒拿訣 | 築基（修為 6） | 金丹（修為 28） | 元嬰（修為 68） |

裝備 API 拒絕未達門檻的技能；前端分別顯示功法等級與境界未達情形。修士境界以現有 **已達最高修為** 的伺服器規則判定，並遵守凡人（0）、煉氣（1）、築基（6）、金丹（28）、元嬰（68）等門檻；不以玩家傳入的屬性、前端選項或本場靈獸境界判定。

## 資料與保護

- `tacticalManuals/{uid}` 保存功法總經驗 `books[id].exp`、已強化的招式等級 `skillLevels[skillId]`、掉落保底、所選流派及最多三個技能 ID；所有寫入只能由後端以登入帳號進行。舊版 `books[id].kills` 在首次寫入時自動轉換為 EXP，並保留原先已解鎖招式（原 3 次擊殺→至少 Lv. 5、8 次擊殺→至少 Lv. 10）。
- 新版戰場以 `tacticalBattleRooms/{id}.manualExp` 與 `manualAppliedExp` 記錄各功法本場累積 EXP 與已領 EXP，避免指令重送重複領取；舊版進行中的戰鬥仍支援 `manualKills` 與 `manualApplied`，按舊版每擊殺 50 EXP 完成結算。戰場每次死亡事件只計入一次，且計算都在伺服器完成。
- `tacticalBattleRooms/{id}.manualDrops` 保存該關已結算的掉落結果。發獎、試煉下一關進度、功法授予與房間結束共同使用資料庫交易；同一關不能靠重送領取多次。
- 客戶端不能自行指定武功傷害、掉落、熟練度、靈獸境界、正解或解鎖條件。伺服器用 `training-access-rules.js` 的玩家修為門檻校驗裝備資格，新開戰場時固定技能快照，戰鬥施法時依角色修為再次檢查技能境界。
- 金丹、元嬰等原有伺服器持有資料繼續保留，不會清空玩家原本修為和金丹，但金丹技能無法再透過體力戰棋操作：舊客戶端傳送的 `type:"skill"` 也會被伺服器拒絕。
- 沒有刪除舊金丹、元神資料，也不會把舊功法重新抽取；只在既有功法的熟練紀錄上進行可重複執行的升級轉換。

## API

- `GET /api/tactical/manuals`：回傳本人功法及技能解鎖狀態。
- `POST /api/tactical/manuals/school`：`{school:"sword"|"body"}`。
- `POST /api/tactical/manuals/loadout`：`{index, name?, skillIds?, apply?}`，儲存名稱與技能或套用指定配置。
- `POST /api/tactical/manuals/equip`：`{skillIds:[...]}`，最多三種已解鎖技能。
- `POST /api/tactical/manuals/upgrade`：`{bookId,targetLevel,expectedGold}`，以目前報價補足功法熟練 EXP。
- `POST /api/tactical/manuals/skills/upgrade`：`{skillId,targetLevel}`，消耗靈石強化一個已解鎖招式。
- `POST /api/tactical/action`：`{type:"manual",skillId,x,y,roomId,revision,requestId}`；有裝備功法時拒絕 `type:"attack"` 普通攻擊，未裝備時允許；全面拒絕 `type:"skill"` 金丹技能。移動、護身、結束回合維持原本 API。
