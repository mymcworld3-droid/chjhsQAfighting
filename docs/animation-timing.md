# 動畫計時

動畫速度以實際經過的毫秒／秒決定，不以繪製幀數累加進度。低幀率時可以少畫幾幀，但同一經過時間的進度應一致。

| 動畫 | 時間來源 |
| --- | --- |
| UI、境界、金丹、法器、團本攻擊與開場特效 | CSS 動畫／轉場的 `ms`、`s` 時長 |
| 頁面平移、修煉建築按鈕 | Web Animations API 的毫秒 `duration` |
| 正式鬥法、鬥法教學的出手與命中 | 固定時間軸與絕對截止時間；晚到的效果使用負延遲追上進度 |
| 悟道修為光球 | `performance.now()` 與 rAF 時間戳，從呼叫飛行時開始計算 |

悟道的飛行、吸收滿條、境界進度帶入與退場共享同一條截止時間軸。首幀延遲或回呼卡頓後，不另行補上一整段飛行或等待時間；完成順序仍是吸收修為後才釋出突破提示。

`requestAnimationFrame` 也可用於繪製排程、量測版面或啟用 CSS 轉場，這些用途不決定動畫時長。新增 JS 連續動畫時應使用 `(目前時間 - 起始時間) / 時長`，不得使用 `frame++`、每幀固定距離或把每幀視為 `1/60` 秒。

`tests/solo-feedback-clock.test.cjs` 比對 15／30／60／120 FPS 的相同時間位置與完成時間，並驗證首幀延遲和突破時序。鬥法的固定時間軸另由 `tests/battle-absolute-time.test.cjs` 驗證。
