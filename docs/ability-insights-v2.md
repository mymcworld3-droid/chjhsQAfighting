# 能力分析圖譜 v3（固定知識點 + 統計診斷 + AI 學習教練）

## 固定分類與題目標記
- 科目只顯示綜合、國文、英文、數學、物理、化學、生物、地科、公民、地理、歷史，順序固定。「綜合」以十科為節點，每一單科固定八個知識點（共 80 個），節點不隨出題範圍或玩家答題順序改變。
- 唯一定義在 `public/cultivation/knowledge-points.js`；前端圖譜、伺服器出題、答題統計與悟道試煉共用。國文包含閱讀理解、文言文、字音字形、詞語成語、語法修辭、篇章結構、文學常識、寫作表達。
- 每題新增 `knowledge_subject`、`knowledge_point_id`、`knowledge_point`，依實際主要考查能力從對應科目的清單選一個，伺服器驗證 ID、名稱、科目一致；缺漏或自創節點會觸發原有重試。`sub_topic/topic/focus/concept` 仍保存原出題範圍，不作為固定能力節點。
- 數學 A/B/甲/乙歸入數學，地球科學歸入地科。範圍可以更細、更自由，但不會增加分析科目或節點。無法合理歸入十科的題目明確留空標記，不硬套學科。
- 共用問道／戰鬥出題、洞天逐題生成、洞天修復、機緣洞天題組均使用固定清單。題庫與既有待答題若沒有標記，仍可作答，不能從其章節或答對與否猜測知識點。
- 所有節點持續顯示，尚未練習的分數為 `null`，不以 0 分冒充能力；綜合只彙整已標記的題目。

## 數據來源
- 長期知識點統計：既有玩家資料內新增 `stats.knowledgePointMapV1[分析科目][固定知識點ID] = {correct,total}`。保留原 `knowledgeMap` 範圍統計供既有獎勵與未完成試煉使用，兩者不混算，不回填缺乏標記的舊題。
- 單人問道在原有玩家交易中累積；鬥法／團本／問鼎在保存固定來源鍵答題紀錄的同一交易中累積，重複回呼不重算；洞天、機緣洞天、悟道試煉在伺服器原有冪等結算交易中累積，使用已保存的題目標記。無標記的舊題與閉關重用的舊錯題不進入新節點統計。
- 近期趨勢及推理題型：登入者自行查詢的最近 **160 筆** \`exam_logs\`，限其 \`uid\`，以 Firestore 已有索引查詢。單人作答新增 \`subject\`、\`subTopic\`、\`questionForm\`、\`cognitiveLevel\`、\`reasoningSteps\`、\`conceptId\` metadata。未分類的舊紀錄不能追溯分類。
- 不從錯題對錯直接推論「粗心」「概念錯誤」；推理題型只依 AI 題目原本標記統計（direct-application、inverse-reasoning、error-analysis、scenario-modeling、data-interpretation、comparison、multi-step、concept-transfer）。

## 分數定義
- 原始正確率：\`correct / total\`，只在有作答時顯示。
- 保守估計：\`(correct + 2)/(total + 4)\`，相當於 Beta(2,2) 先驗平均。用以避免 1/1 就顯示 100%，**不是已校準的知識追蹤模型或學測分數**。
- 0 題：無資料，圖表 \`null\` 留白，不當作 0 分。
- 1–4 題：需要更多題（不可斷定能力）。
- 5 題以上且估計 <60%：優先補強；60–77%：持續鞏固；78% 以上：表現穩定。只是產品內部練習提示，非學術評鑑切點。
- 信度標籤僅依樣本量：少於 8 題 = 不足，8–19 題 = 中等，20 題以上 = 較高；不代表嚴格統計檢定。
- 近七日 vs 前七日變化：以最近 160 筆**已分類**的紀錄估算，兩段各至少五題才計算百分點變化。不同題型與難度不等價，結果僅供自己檢視學習趨勢。
- 分析只呈現上述十科，不增加「其他領域」；無法分類的題目保留在一般答題紀錄中。

## AI 學習教練
- 玩家必須主動按下「讓 AI 制訂補強計畫」；\`POST /api/learning/ability-coach\` 使用 Firebase A ID token 進行身份驗證。
- 傳給 AI Router 的只有各單元的 \`subject/topic/total/correct\`、部分優先單元、選定時間區間彙總，以及推理題型的 \`name/total/correct\`。**不傳**姓名、Email、UID、題目文字、答題選項或完整歷史。
- 模型不得改寫統計分數、直接儲存練習紀錄或產生獎勵。回傳方案與統計結果明確分離。
- 伺服器驗證、欄位截斷、AI 建議題目必須存在於傳入摘要；一分鐘冷卻，每 UID 滾動 24 小時最多六次（目前記憶體防護，若多個 Render instance 或重啟，需要共享限流／配額）。
- 當 AI 無服務或未配置時，顯示可理解的錯誤訊息，統計與雷達圖不受影響。
- 接入現有 \`ai-router\`，不新增或外洩 API key。

## 驗收建議
1. 0 題玩家：顯示「尚無紀錄」，不產生虛假的 0% 弱點或 AI 成績。
2. 1/1 正確：顯示原始正確率 100%，保守估計 60%，標註樣本不足。
3. 12 題只答對 2 題：進入優先補強；另一領域完全未作答不列弱點。
4. 按數學／英文切換：只顯示選取科目的單元、總題數、AI 建議。
5. 近兩週有足量已分類紀錄時才顯示可比較的變化；前期紀錄不足時顯示 —。
6. 不帶 \`questionForm\` 的紀錄不進入推理題型分數，已有標記的才納入。
7. 登出後換帳：不能顯示上個 UID 的近期答題紀錄或 AI 建議。
8. 無 AI 金鑰、服務暫斷及觸發限流：不阻斷其他能力圖表。
9. 手機與直式版面：圖表與卡片不溢出；洞府折疊時資料不會變成跨帳號殘留。

## 本次延伸：圖譜顯示與 Math input error 容錯
- 能力圖譜支援「知識掌握／推理能力／學習趨勢」三種明確模式；科目切換採橫向捲動避免畫面擁擠。雷達圖只有至少三個已觀察維度時出現，其餘使用橫向長條，未知分數留白。
- 無資料／圖表元件故障時不顯示假的 0% 雷達圖，而顯示可閱讀的狀態文字；下方能力細項與規則建議仍可正常查看。
- 自動產題品質檢查現在驗證 TeX 定界符、數學括號與環境；失敗的 AI 題目依原本重試策略處理，不直接提供壞公式。
- 所有共用 quiz-math 渲染入口，遇到不完整公式就轉為 HTML escaped 的原文；MathJax 運行期出現 merror 或例外時，也改為不再由 MathJax 解析的可閱讀原文（tex2jax_ignore）。
- AI 補強建議的「答對 x/y 題」只能從統計資料產生，不接受模型猜測的樣本數。如果 AI 回傳格式錯誤或服務無法使用，顯示**明確標記的規則式備用計畫**，不假稱 AI 已成功分析。
- 該防護措施旨在減少畫面上的 Math input error；無法保證偵測所有不合法的 LaTeX 指令，因此保留 MathJax noerrors 與共用渲染的執行期容錯。
