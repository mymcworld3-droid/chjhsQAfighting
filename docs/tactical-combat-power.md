# 體力分支｜戰棋戰力評分 v1

適用分支：`stamina-battle`（`window.QA_MANUAL_TRAINING_ONLY === true`）。這是**展示用、非傷害倍率、非配對分數**。不變更怪物攻擊、戰棋體力上限或玩家資料格式。

## 為何要換

傳統戰力原本由角色攻擊與生命、金丹品級（最高可單獨計 20,000 分）及已裝備法寶構成。但體力戰棋停用了金丹技能，戰棋伺服器也不帶入裝備法寶效果；繼續加分會使角色的戰力數字與可用招式脫節。

## 分數公式

令 `A` 為正式戰棋可用的攻擊力，`H` 為包含永久境界與有效元嬰屬性加成後的最大生命：

- 基礎戰力 `B = round(2A + 0.2H)`。
- 只處理**已取得、已滿足功法熟練 Lv.1/5/10、符合玩家最高已達境界且已裝備**的最多三招。同一底層招式只能計一次。僅擁有書籍、未解鎖或未裝備，一律不加分。
- 招式 `i` 的未加權評分 `R_i = round(A × (D_i + Q_i + U_i))`，其中：
  - `D_i = min(5,傷害倍率) × 2/max(2,技能體力)`，已含目前招式強化等級的實際倍率與耗體。
  - `Q_i = min(4,射程) × 0.025`；無固定射程按 4 格計入，不會讓長線攻擊無限加分。
  - `U_i` 是有限度的戰術加成：突進橫斬 0.12、劍陣 0.14、飛劍 0.10、拳掃 0.10、連推 0.15、擒摔 0.22；額外 T 形 0.04、遠線推退 0.12、推退 0.08。蓄勢因放棄當回合行動，只計 `0.45+0.05×(7−目前耗體)`。
- 依 `R_i` 由大到小排序：`S = R_1 + round(0.4R_2) + round(0.2R_3)`。
- **戰棋戰力 `P = B + S`**。

上述係數是可調整的設計權重，並非由勝率估計得出的機率或真實 DPS。第二、第三招權重降低，是為了避免將三個可供選擇的招式當成同一回合全部施放。

## 判讀例子

攻擊 200、最大生命 1,000，基礎戰力為 600。只裝備 `流風斬`（Lv.1，2 體力，1.15 倍傷害，射程 3 格）時，招式評分約為 245，總戰力為 **845**。即使其他功法升級，只要沒有更動可用裝備招式，戰力就不會額外增加。

## 資料來源及介面

- 純計算邏輯：`public/cultivation/tactical-power-rules.js`，同時能被 Node 與瀏覽器載入。
- 當前角色：`combat-power.js` 使用 `getCombatStats()` 投影可用攻擊／生命，境界取 `QATrainingAccessRules.score`；功法狀態只能來自經登入驗證的 `GET /api/tactical/manuals` 或相同 API 成功保存後的回應。
- 登入、自動取得／掉落功法、裝備變更、技能升級時同步；切換使用者清除本機戰力快取。沒有資料時顯示基礎值，註明功法未同步，而不是錯誤宣稱完整戰力。
- 功法閣、個人資料及傳統狀態頁使用相同分數；非本人玩家的獨立功法資料目前沒有開放讀取，因此他人個人資料只標示**基礎戰力（功法未同步）**，不造假完整分數。
- 保留舊 `calculateGoldenCorePower`、`calculateArtifactPower`，其他沒有設定此分支旗標的玩法仍維持舊公式。

## 數據驗證重點

1. 已裝備且符合功法 Lv.／修士境界才計分。
2. 升招式傷害、降低蓄勢耗體可以提高分數。
3. 額外擁有功法、提高沒有裝備的熟練度，不會加分。
4. 可用技能增加時，戰力不應下降；第二、第三招遞減權重。
5. 角色跨帳號或 API 請求晚到不應顯示上一個人的功法。
6. 戰力**不參與實際傷害、靈獸強度、體力消耗、勝負或配對**。
