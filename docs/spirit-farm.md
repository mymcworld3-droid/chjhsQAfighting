# 靈田：第一版

入口位於修煉場景左上角「靈田」。沿用原有導覽與畫面比例，田園為青綠、宣紙與生成場景的組合，保留田畦間距、後窄前寬與超出田格的靈植。

## 快捷操作

- 選好種子後，點空田直接播種；點未灌溉的幼苗免費灌溉；點成熟靈植直接採收。已灌溉的植株與未開墾的田地會開啟單畦詳情，不自動花費靈氣或收成。
- 「播種 N 畦」依目前種子數，從後排往前填入已開墾的空田，保留其他植株；「灌溉 N 畦」免費處理所有仍在生長且未灌溉的靈植；「採收 N 畦」採收全部成熟靈植。這三個快捷按鈕放在田地上方。
- 「全部施肥」「全部驅蟲」先顯示符合條件的畦數與合計靈氣花費，靈氣不足時停用；仍可免費灌溉或在單畦詳情選擇要照料的植株。整批照料不處理成熟、已完成照料、空置或鎖住的田地。
- 整批操作各只發出一筆請求、一筆交易；播種數量依現有種子預覽，整批照料靈氣不足時完全不執行。若傳送途中部分植株成熟，伺服器略過並只收取其餘合格植株的花費。
- 手機的種子列移到田地上方，頂部整合返回、靈氣、領氣與同步；單畦詳情、倉庫、建設與長說明可收合。採收訊息依靈植合併數量，變異發現仍會提示。

## 生長與經營

新玩家取得 3×3 田地，先開放第一排三畦；種子為青露草 6、赤穗花 3、月華蘭 1，另有 6 點靈氣。收成可逐排開墾至九畦，或用於換種子、修水渠、兌換木材。

| 靈草 | 自然生長 | 基本收成 | 喜歡相鄰的靈草 | 12 株可換 |
| --- | --- | --- | --- | --- |
| 青露草 | 10 分鐘 | 2 株 | 赤穗花 | 靈木 ×1 |
| 赤穗花 | 45 分鐘 | 3 株 | 月華蘭 | 百年靈木 ×1（築基初期） |
| 月華蘭 | 180 分鐘 | 5 株 | 青露草 | 雷擊木 ×1（金丹境） |

- 成長依伺服器絕對時間計算，離線持續生長，成熟後不枯死、不扣除收成。重新整理、換裝置或關閉畫面不重設時間。
- 每株灌溉一次，免費縮短原生長時間的 10%，提高一點品質。施肥一次消耗靈氣 2，縮短原生長時間的 15%，提高一點品質。未經照顧仍能得到基本收成。
- 採收時上下左右有對應共植作物，提高一點品質。良品（2 點）多收 1 株，上品（3 點以上）多收 2 株；一鍵採收先計算所有田地的共植狀態，再一併清空。
- 種植時有 12% 機率出現可驅散的靈蟲。消耗靈氣 1 驅散可提高一點品質；忽略靈蟲不降低基本收成，也不停止成長。
- 變異機率為 2%，施肥另加 5 個百分點、共植另加 3 個百分點。隨機值在種植時固定，採收時依條件判定；重整、重試不重抽。變異多收 1 株並留下 2 顆種子，普通採收留下 1 顆。倉庫顯示各種變異的收集數量。
- 種子交換：青露草 1 株換本種種子 1 顆；青露草 3 株換赤穗花種子 1 顆；赤穗花 3 株換月華蘭種子 1 顆。
- 開第二排需青露草 6、赤穗花 2；第三排需青露草 12、赤穗花 6、月華蘭 2。
- 修復水渠需青露草 4、赤穗花 2。左側三畦自動灌溉，原生長時間合計縮短 25%；已種下且仍在成長的左側植株也會獲得尚未取得的加成。成熟植株不再追加照顧加成。
- 作答後返回靈田可按頂部「領氣」，從今日最近 80 筆已保存紀錄認領不同題目的作答，每題 1 點、台灣日最多 20 點、持有上限 60。答對、答錯都計入；跳過、未來時間、跨日、別人的紀錄與同日相同題目不重複計入。以既有作答紀錄為依據，沒有新增一套權威答案驗證。讀取靈田不自動掃描答題歷史。

以上數值位於 `public/cultivation/spirit-farm-rules.js` 與 `spirit-farm-api.cjs`，為第一版產品設定，後續可依遊玩節奏調整。材料兌換沿用已達境界判斷，材料進入既有 `materialSystem.inventory`，可供本命法器鍛造使用；鐵材、團本印記、高階木材仍維持原有來源。

## 儲存與操作一致性

主專案 A 的 `spiritFarms/{uid}` 為伺服器專用資料，存放田地、種子、收成、建設、靈氣與有限操作紀錄。使用獨立文件，普通答題更新 stats 不會覆寫靈田。瀏覽器不能透過通用資料 API 直接讀寫此集合。

`GET /api/spirit-farm` 驗證主帳號後取得自己的田園；新玩家在交易內初始化一次。`POST /api/spirit-farm` 執行田務，UID 取自已驗證的登入身分。生長時間、價格、數量、隨機值與兌換材料由伺服器決定，忽略客戶端自訂獎勵。

每次操作綁定 requestId、當前 revision，單畦照料與採收另綁植株 ID。整批操作的田地、數量與價格由伺服器依當前狀態決定，共用 `workPlan` 與畫面預覽核對；播種的各畦隨機值獨立且在交易重試時固定。在同筆交易內完成扣款、加物、更新田地，最近 64 筆重試回傳原結果，無法重複入帳；更早已移除的請求仍會因過期 revision 被拒絕。同時操作兩個不同請求時，只有符合當前狀態者會成功。

瀏覽器按帳號保存尚待確認的單筆操作。逾時或 503 會保留原操作供重試；重整後重新開啟靈田會先確認該操作。明確的輸入錯誤清除待確認項，狀態衝突重新同步，跨帳號的延遲回應不更新畫面或背包。沒有持續 API 輪詢；只有田園可見時更新本地倒數，修煉入口的採收提示只使用已知快照。

## 素材

使用內建 imagegen 生成新素材，再以 ImageMagick 等比例縮小並壓縮成 WebP，保留靈草透明背景，沒有取代現有素材。

- `public/assets/spirit-farm/garden.webp`：靈田場景，1400×933。
- `public/assets/spirit-farm/herbs.webp`：三種靈草的透明圖集，1200×400。
- 完整生成指令見 [spirit-farm-art.md](spirit-farm-art.md)。

## 驗證

`tests/spirit-farm.test.cjs` 使用真實 SQLite 與 D1 adapter 驗證生長、跨日、身分隔離、原子兌換、失敗回滾、重送／並行操作、共植採收、水渠、變異與靈氣限制，並涵蓋批次扣款、種子不足、成熟時間跨越與預覽一致性。`tests/spirit-farm-client.test.cjs` 驗證單點操作、批次只送一次、逾時保留、重新整理重試、跨帳號回應與頂部資訊、離線訊息與儲存失敗。另以瀏覽器連接本地 SQLite 服務檢查手機／桌面及實際直式、橫式遊戲比例，實際完成九畦播種、灌溉、施肥、驅蟲、採收，以及伺服器已完成但回應遺失後重整重送；不存取正式玩家資料。

更新前端後執行 `npm run build:module-versions`；完整回歸執行 `npm test` 與 `npm run check:module-versions`。
