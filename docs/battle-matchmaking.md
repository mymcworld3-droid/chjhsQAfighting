# 鬥法同時配對與房間合併

## 同時開房

兩人最初查詢都看不到等待房時，允許各自建立一間。等待監聽與每 1.1 秒的補查會讓 ID 較大的房主，原子地加入較小的等待房並刪除自己的房間。只有最後成功提交的交易才回傳加入成功；Firestore 丟棄的交易嘗試不保留旗標。

合併開始時保存來源房、目標房、玩家與本次配對序號。來源房刪除通知即使先於交易回應抵達，也不會把玩家送回宗門。成功後切換到目標房；回應遺失時查實際成員確認結果。連查詢也暫時失敗時，下一輪先確認同一個目標，不另配一間。

每次房間訂閱有獨立序號；已解除訂閱但仍在佇列中的舊回呼，不能覆寫新房間或結束新會話。

## 活躍等待與查詢窗口

等待房的過期時間以建立時間與房主最近心跳的較新值判定。仍在線的房主等待超過 90 秒，房間繼續可加入；失去心跳的房間則會過期。

舊過期等待房可能佔滿查詢的前 80 筆。使用文件游標分頁，單輪最多讀 4 頁，尚未找到時保留游標，下輪接續。即時監聽若已包含合適候選，直接使用，不額外輪詢。維持既有查詢欄位與 Firebase C 加入／刪除規則，不需要新增複合索引或放寬權限。

## 取消與切換帳號

重設會話會遞增配對序號；每次非同步搜尋、交易與建房完成後重新確認序號、UID 與離開狀態。已取消的請求不可重新打開鬥法頁。

晚到的未配對自有房會刪除；晚到但已配到對手的房，按實際成員結束為投降，避免讓對手卡住。新一輪已恢復同一房時，舊請求不能清理新會話。取消未配對房仍不呼叫戰鬥獎勵 API。

## 驗證

`tests/battle-matchmaking-race.test.cjs` 使用實際控制函式、交易重試与房間回呼，重現刪除通知早於提交回應。涵蓋雙方同時搜尋／建房、三人競爭、失敗交易重試、過期回呼、心跳續命、過期查詢窗口、回應遺失、延遲建房與取消。
