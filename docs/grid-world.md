# 青雲界：種子生成的共享格狀世界

工作分支：`grid-world`。登入完成、雲幕打開後進入大世界；原有養成、自由問道、鬥法與團本繼續使用原功能。

## 已可遊玩的流程

1. 出現在問道宗。宗門區域預先標示，野外保留個人探索迷霧。
2. 點格沿四方向道路逐格行走；途中可改道、停止。拖曳或點小地圖只移動鏡頭，按「回到角色」恢復跟隨。
3. 點任務即可標示目標並尋路。探索視野半徑 15 格，點選迷霧中的目的地也會沿可通行地形尋路，途中逐步揭開地圖；長路線分段自動接續。
4. 點靈材、寶箱或妖獸，確認後走到相鄰格互動。採集、寶箱與妖獸獎勵的資格各自保存。
5. 在原地展開 8 × 8 局部戰場。完成兩題補能，或略過剩餘補能，再移動、普攻、神通、防守或操作陣眼。
6. 勝利材料直接進入現有 `materialSystem.inventory`，修為與靈石直接進入現有玩家資料。完成四項初始目標可領 6 修為，達到築基後可帶材料使用既有鍛造坊。

地圖為 1000 × 1000 方格，依世界種子按需生成 32 × 32 區塊。問道宗、青竹林、古陣山口採用固定新手模板，東側道路接往外圍生成世界；外圍包含海洋、海岸、森林、山地、雪原、荒漠、濕地、分級妖獸、秘境、結構與連續礦脈。玩家不占探索碰撞格；同格玩家折疊顯示人數，點擊可查看名單與角色資料。附近道友可直接邀請既有團本或指定對手的鬥法；陌生道友交流先經現有好友邀請流程。

地景裝飾也由相同種子決定：竹林混合三種竹叢與灌木，石域的散石保留相鄰空格；營地有接起轉角的柵欄、物資、柴堆及營火，遺跡有斷牆、石柱與碎石。周邊配置避開道路與其他物件，不新增碰撞資料。十五棟建築維持原本的單一正面圖片和正門方向；妖獸、船隻、柵欄、城牆、城門及橋梁依方向選擇圖片。道路依鄰格連接，地面材質跨格延伸並在不同生態的交界混合。

柵欄與圍牆以格為單位自動連接，北／東／南／西各占一位元，形成 16 種狀態。相鄰同材質地格互相伸出半段；孤立格只剩柱子，直線圍牆省去高柱，轉角、T 字和十字使用單一中心接點。城門與營地入口依通道方向銜接兩側，保留通道；不連接斜角或不同材質。先讀取一格外圈再裁切畫面，避免捲動、跨區塊或迷霧揭露時接錯。

## 戰棋規則與養成投影

- 移動每回合一次、最多兩格，按實際路徑計算；不走斜線，不穿過敵人或障礙。
- 普攻／神通／防守／陣眼擇一，與移動先後不限。結束回合時，尚有動作未使用會提醒一次。
- 基礎靈力起始 1，每個新回合回復 1，答對每題額外 +1，上限 8。答錯及略過不會剝奪移動、基礎普攻與防守。
- 敵人先執行已公布的紅格攻擊，再依虛線預告移動；隕石在敵人移動後落下。陣眼提供所有流派都能使用的降攻、破盾解法。
- 玩家戰鬥數值由 `trustedRaidPlayerSnapshot` 從伺服器玩家紀錄與裝備圖鑑重新計算，包括境界生命、金丹、元嬰、化神與法寶，前端不提交傷害或養成數值。
- 本回合至少一題答對時，普攻沿用既有團本的答對出手被動；兩題皆錯／略過仍能造成投影攻擊力的基礎傷害。這是第一版戰棋的回合轉換規則，非將舊鬥法逐題結算原封套入兩題補能。

| 金丹 | 主動戰術 |
| --- | --- |
| 雷霆 | 減傷架盾，反擊三格內攻擊者 |
| 星隕 | 指定四格內落點，預判敵人移動後的十字爆破 |
| 滄海 | 推退敵人，留下減速與傷害潮域 |
| 劍心 | 沿可通行路線突進後斬擊 |
| 太初 | 回復生命，歸元納氣分支可將實際治療轉傷 |
| 無垢 | 破盾、停頓與解除危險區域 |
| 陰陽 | 依損失生命回復與強化反擊 |
| 未結丹及其他既有丹 | 共用靈息破擊；養成不被刪除 |

補能優先採用伺服器保存的學制、科目與範圍，批次生成兩題，答案僅保留在伺服器。AI 服務不可用時使用已核對的基礎題，畫面顯示實際科目。每題結果寫入既有答題紀錄，可展開選項、正解與解析；可用現有數學排版與安全備援。第一版最多 50 回合，撤離不扣除既有材料。

## 獎勵與共享事件

- 採集：每個點每日個人一次，台灣時間換日；不被其他玩家搶走。
- 寶箱：每個點個人首次一次。
- 妖獸：每個點每日第一次勝利發獎；其後可無獎勵重打練習戰術。
- 初始任務：個人四項目標完成後一次領取，與材料、修為變更同一交易提交。
- 青溪橋：全服 20 次貢獻，每人每日可投入靈木 ×2。完成後南側兩格斷橋成為可行走捷徑。
- 古陣：全服 60 次貢獻，每人每日可投入玄鐵 ×2。完成後北方封印格開放，所有玩家可前往個人古陣秘藏。
- 採集、寶箱、貢獻、回答與勝利由伺服器交易驗證，並保存操作識別碼；重送、斷線重試及同時點擊不會重複加材料。

## 同步與存檔

`POST /api/world` 使用既有 A 專案身分驗證，憑證放 Authorization header。地形與尋路共用 `public/world/world-core.js`，隨靜態資源版本快取。完整生成規則、變更存檔與模擬器見 [seeded-world.md](seeded-world.md)。客戶端取得種子與生成版本後自行重建附近地形；伺服器只讀取、傳送有修改且版本不同的附近區塊。

目前即時層選用 **Render 單一 Node 程序的記憶體房間 + SSE**，沒有增加 Workers 或逐格 D1 寫入。附近半徑 15 格顯示玩家；新路線帶開始時間與每格時長，各瀏覽器以絕對時間播放。重複相同路線不會每個畫面／地格重送。背景巡檢只檢查記憶體，不查詢 D1。

位置與迷霧在抵達、離開、連線關閉，以及長路線的每 60 秒檢查點合併保存。存檔失敗保留待存狀態並退避重試，避免配額失敗後高頻重送。中途斷線停止在最後到達的地格，離開附近名單；重連或程序重啟後從持久檢查點恢復。若程序直接崩潰，最多回到上一個位置檢查點；已提交的戰鬥與獎勵會保留。

| 持久資料 | 位置 |
| --- | --- |
| 個人位置、迷霧、資格、任務、局部戰鬥 | A / `worldPlayers/{uid}` |
| 世界種子與版本、全服修橋／破陣、變更區塊版本索引 | A / `worldEvents/main` |
| 僅有修改地格的區塊 | A / `worldChunks/{worldId}:{cx},{cy}` |
| 材料、修為、靈石、答題統計 | 原本 `users/{uid}` |
| 題目、選項、答案與解析 | 原本 `exam_logs` |

使用目前 `GAME_DATA_BACKEND=d1` 設定時，以上持久資料走既有 D1 文件儲存層，不需新增 SQL migration、Firestore listener 或另一套身分服務。維護模式會由全域 API 閘門阻擋。`worldPlayers`、`worldEvents`、`worldChunks` 不開放一般瀏覽器資料 API 直接讀寫。

**部署須維持單一 Render 執行個體／Node 程序。** 目前未使用跨機即時訊息代理；在多個副本部署會拆開在線玩家名單。擴容前須將即時房間抽到共享 broker／Durable Object，並將位置控制權加上跨節點租約。此次沒有宣稱完成多人負載或正式線上部署測試。

## 本地驗證

大世界沿用既有墨金主題、正式頁首及「宗門／修煉／坊市／仙盟／設定」五鍵導覽，未另建探索用底部列。地圖與互動面板位於原頁首與導覽之間；戰棋的回合操作列出現在導覽上方。自由問道與功能選單在地圖上方，點擊原標題可返回大世界。外層繼續使用原本的 `stage.html`，橫式 1280 × 720、直式 360 × 640 等比縮放並保留黑邊。

```sh
npm ci
node --test tests/world-*.test.cjs tests/battle-matchmaking-race.test.cjs
npm run build:module-versions
npm test
npm run audit:code
node scripts/capture-grid-world.cjs
```

畫面驗證使用隔離的測試帳號、記憶體交易資料與真實 API／前端入口，不會登入真實帳號或寫入正式資料。每張截圖均經過正式 `stage.html`／`index.html` 與原樣式，涵蓋 1440 × 900、390 × 844、1194 × 834、360 × 640、1280 × 720 瀏覽器視窗。腳本比對接入地圖前後的五鍵 HTML、配色與尺寸，檢查探索／補能／戰棋的導覽可見性、黑邊及固定比例、切頁與標題返回、戰鬥時阻擋切頁，並驗證兩個瀏覽器看見彼此、點格移動、迷霧中的目的地移動、遭遇、作答存檔、繼續補能、確認移動、移動後防守、回合結束、重載續戰與頁面溢出。

需要本地 Playwright Chromium、Tailwind 3、Noto Serif TC／Noto Sans TC 與 Font Awesome 6.4。可用 `WORLD_CHROMIUM_PATH` 指定瀏覽器，`WORLD_UI_DEPS` 指定樣式／字型依賴目錄，`WORLD_TAILWIND` 指定由 `public/**/*.html`、`public/**/*.js` 產生的 Tailwind CSS。預設依賴在 `/tmp/grid-world-ui/node_modules`，CSS 在 `/tmp/grid-world-tailwind.css`；依賴僅用於隔離截圖，不寫入正式套件。

截圖與結果放在 `docs/design/grid-world/`，另驗證生成區域的秘境機關、重載後續解、探索獎勵，以及靠岸乘舟和實際水路移動。模擬器截圖與匯出範例在 `docs/design/seed-world/`。分支只交付此可玩閉環，不自動合併到 `main`。

## 後續階段

局部戰場目前是個人戰場，其他玩家可穿過並看到交戰標記；尚未把「申請支援」做成多名角色加入同一局部戰場。現有團本仍可多人組隊，附近邀請會接入既有團本／鬥法。下一階段需另做戰場參戰名單、支援輪次、掉線代操作與參戰獎勵資格，再擴充更多事件與題目能力分析導航。
