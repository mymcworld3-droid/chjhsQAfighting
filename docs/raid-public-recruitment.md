# 公開清霜團本招募

## 玩家操作

- 「秘境試煉 → 公開隊伍」列出伺服器核可、尚未開始、房主在線、未滿四人且未過期的隊伍。
- 每張卡片顯示房主名稱、普通／困難／極境、現在人數、準備人數與加入鍵。每 12 秒更新，另有手動刷新。人數以在線成員為準。
- 「快速組隊」只配對公開房間，若無可用則建立一間公開房。「私人開房」預設私人，仍可使用六碼房碼邀請好友。隊長可在等待室切換公開／私人。
- 加入與更改公開狀態都走 `/api/raid/room`，包含 `list-public`、`join-public`、`set-visibility`。其餘邀請、準備、開戰與中途重連仍沿用原邏輯。

秘境總覽使用單一垂直捲動區，Boss 卡片不再強制撐到畫面底部，公開隊伍依自然高度排在卡片之後。手機的難度、組隊與邀請碼操作整列排在立繪下方，主要按鈕至少 48px 高、文字 15px；窄螢幕與橫式可向下捲到全部隊伍。說明以人數、合作機制、入場境界與獎勵為主，移除重複介紹與開發用語。招募讀取失敗時顯示精簡提示，技術錯誤留在主控台。

## 安全與權威

- 列表只提供可公開的 `roomId`、房主**名稱**、難度、人數、準備數。**不提供私人代碼、UID、戰力快照或答題票證**。
- `join-public` 在 Firestore 交易內重新檢查：真的公開、等待狀態、房主在線、未過期、最多四位成員、實際清霜難度／使用者已達境界。滿房／解散／切換私有／提前開戰立即拒絕，沒有虛假成功。
- 確認使用 Firebase A 的可信角色快照與入場券，加入時不扣券；與原先機制相同，到隊長開戰才統一扣券。
- 舊房間缺少 `visibility` 欄位時視為私人，避免意外公開。離線、過期、已開戰、滿房名單不顯示。
- 公開招募純讀取不動玩家 A 專案資訊；成員的 C 專案資料與連線照既有授權機制取得。
