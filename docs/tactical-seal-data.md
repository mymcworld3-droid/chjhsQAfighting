# 體力分支／問道試煉：封印陣眼資料契約（第一階段）

此文件記錄 `stamina-battle` 分支封印關卡 **layoutVersion 4** 的既有規則，
並定義之後「陣眼圖片、效果範圍、情報面板」必須共用的單一資料來源。
本階段整理單一資料來源、必要的規則參數引用，以及既有戰場標記的標籤／顏色來源，**不改變戰鬥判定與操作方式**。

## 四種陣眼

| kind | 顯示名稱 | 範圍 | 既有戰鬥效果 | 破除後 |
| --- | --- | --- | --- | --- |
| `shield` | 護靈陣眼 | 曼哈頓距離 ≤3 | 對範圍內靈獸造成的非穿透傷害乘上 0.65 | 該座陣眼的減傷來源消失 |
| `hazard` | 妖煞陣眼 | 動態預告格，沒有固定三格半徑 | 偶數回合在玩家目前地格留下預告；回合結束仍站在該格時，失去最大生命 12%（至少 1 點） | 最後一座妖煞陣眼被破除時清除現有預告 |
| `rage` | 御獸陣眼 | 曼哈頓距離 ≤3 | 範圍內靈獸造成傷害乘上 1.25 | 該座陣眼的增傷來源消失 |
| `maze` | 迷蹤陣眼 | 指向連動石障，沒有固定光環 | 關聯一個指定石障（若有配置） | 陣眼破除後移除該石障 |

- 以上「距離」使用 `abs(dx)+abs(dy)`，**不是圓形、方形或視線距離**；護靈與御獸光環不會被牆阻斷。
- 同一種增益若有多座相互重疊，現有實作使用 `some(...)` 判定，**不累加**。
- 陣眼是位於一個格子的固定可攻擊目標，初始耐久 2，符合攻擊命中時減少 1。生命歸零後 `activated=true`。
- 既有第三版封印關卡使用「走到陣眼格上啟動」規則；**不能直接套用第四版可攻擊陣眼描述**。
- 原有答題、技能耗體、回合與攻擊命中計算維持不變。

## 共用 API

檔案：`public/cultivation/tactical-rules.js`，同時用於 Node 伺服器與瀏覽器端
`QATactical`。

| API | 用途 |
| --- | --- |
| `SEAL_TYPES` | 不可變資料：類型、名稱、簡短提示、標籤、顏色、效果文字、範圍語義、機制參數、破除描述與提示 |
| `SEAL_KINDS` | 由共用類型目錄產生的不可變順序；保留既有種子碼生成結果，不要任意調整類型插入順序 |
| `SEAL_MAX_DURABILITY`、`SEAL_HIT_DAMAGE` | 關卡初始化與命中扣除共用的耐久規則 |
| `sealDefinition(kind)` | 取得單一類型定義；未知類型回傳 `null` |
| `sealInfo(state, {x,y})` | 取得某座陣眼即時快照，包含耐久、是否仍可攻擊及連動障礙；無效／舊版狀態回傳 `null` |
| `sealInfos(state)` | 列出本場全部第四版陣眼快照；非第四版回傳空陣列 |
| `sealEffectCells(state, {x,y})` | 護靈／御獸回傳有效曼哈頓範圍；妖煞回傳實際預告格；迷蹤回傳空陣列 |

### 情報介面接入範例

```js
const seals=QATactical.sealInfos(battle);
const selected=QATactical.sealInfo(battle,{x:4,y:2});
const influence=QATactical.sealEffectCells(battle,{x:4,y:2});
```

現有的 `tactical-combat.js` 戰場目標摘要透過 `sealDefinition(kind).shortEffect` 顯示短名稱；
`tactical-renderer.js` 原本的圓形陣眼暫時保留，但標籤與未破除的顏色改由 `sealInfo(state, point)` 取得，
舊版第三代關卡維持原本「陣」字標記。第二階段已接入 AI 生成的四類／三狀態透明 WebP 圖集，並保留圖片載入失敗時的文字圓形標記。

不要把 `sealInfo` 的計算結果寫回 `battle.objective`。
快照中 `range` 與 `gate` 是副本資料，不直接引用戰場狀態；適合在介面短暫顯示。

### 後續階段注意事項

1. 渲染「影響範圍」時區分 `range.kind`：`manhattan`、`warning`、`linked-block`；不可將後兩者硬畫成三格菱形。
2. 妖煞的預告範圍以 `objective.hazards` 當下資料為準；若沒有預告，不畫危險格。
3. 效果範圍、角色預告、技能瞄準範圍與角色立繪應分不同 Canvas 圖層，危險紅框優先。
4. 情報面板與首次教學不能代替伺服器端的實際技能命中驗證。
5. 陣眼受損／破除應依 `hp/maxHp/active` 決定，不修改伺服器的結算時機。
6. 第一階段只統一既有標記的文字和色彩來源；圖片素材、正式範圍圖層與情報視窗安排在後續階段。

測試：`node --test tests/tactical-seal-metadata.test.cjs tests/tactical-layout-v4.test.cjs`。

驗收：第一階段專屬測試共 9 項，涵蓋真實種子關卡、舊版相容、資訊快照不改寫狀態、現有畫面資料綁定及核心戰鬥數值。


## 第二階段：B＋C 陣眼圖片

- 素材：`public/assets/seals/seal-atlas.webp`，512×384、RGBA WebP、約 73 KB。
- 圖集排版為 **4 欄 × 3 列**，每格 128×128。
  - 欄依 `SEAL_KINDS`：`shield`、`hazard`、`rage`、`maze`。
  - 列依耐久狀態：完整（2/2）、受損（1/2）、破除（0/2）。
- 以原始 AI 生成圖重新裁切、透明去背與壓縮。地面符陣和懸浮晶核整合為一張帶透明度的圖集；不需要逐個網路請求。
- 當 `layoutVersion===4` 且為封印關卡，才懶載入圖集；其他模式不多下載圖片。
- 在戰場地面預告層之上、人物／靈獸及生命條下方繪製，確保角色不被蓋住。
- 圖集下載失敗或圖片尚在載入時，保留原本的文字圓形標記作為後備。
- 陣眼依實際 `hp/maxHp/activated` 選擇圖片，現有傷害與結算不變。破除後保留殘破石盤。
- 第三版舊封印關卡維持文字標記，不誤套第四版可攻擊素材。
- 依照第二階段範圍限制：不新增「影響範圍高亮」與「陣眼情報」面板，這兩項按原規劃留待第三、五階段。


## 第三階段：陣眼作用範圍視覺化

- 護靈（藍）、御獸（橙）：呼叫 `QATactical.sealEffectCells` 取得**真正的曼哈頓距離三格**，同型重疊只畫聯集，不用顏色深淺暗示加成疊加。光暈低透明，菱形外緣點線，不蓋住攻擊預告與人物。
- 妖煞（紫紅）：只有 `objective.hazards` 產生實際預告時，才在對應地格留下細小紫紅角標。切換至單座檢視時，另以虛線連接陣眼和危險格；**沒有預告就沒有範圍**。
- 迷蹤（青綠）：只有 `gate` 仍在目前 `blocks` 中時，才畫陣眼至石障的虛線與石障四角標示；沒有連動石障不畫虛構範圍。
- 顯示模式：全部（預設、低透明度）→單座（集中顯示一座）→隱藏→全部，另有「下一座」切換單座目標及主動定位。切換純本地 UI、不扣體力、不發送指令；已破除陣眼自動退出目標列表。
- 狀態推導快取於 `TacticalRenderer.update`，Canvas `draw` 只畫已推導結果，不在動畫每一幀重新算座標；拖曳與縮放仍依即時相機座標畫出。
- 繪製順序：地形與氛圍 → 陣眼低透明度地面作用區 → 妖煞原有危險格與移動／攻擊預告 → 障礙物 → 陣眼連動線／角標 → 紅色攻擊外框 → 懸浮靈核圖集 → 玩家、靈獸與血條。所有危險預告的優先權不變。
- UI 小型工具列採獨立 DOM，不放在直式戰場原本隱藏的標題列內、不占用左右四分之一圓的技能按鈕，也不新增任何會誤觸移動／攻擊的地圖手勢。
- 第三階段只做影響範圍和純顯示切換，陣眼詳細資訊面板及完整教學留待後續階段。
- 回歸測試：`node --test tests/tactical-seal-ranges.test.cjs tests/tactical-seal-art.test.cjs tests/tactical-render-layering.test.cjs`。


## 第四階段：教學、可攻擊識別與真實命中提示

- 僅對 PvE 第四版封印模式啟用；舊第三版啟動陣眼不顯示可攻擊提示。
- 玩家第一次進入新版封印關卡，會看到可略過的短教學：懸浮晶核可破壞，先切換攻擊技能，選擇射程／方向命中的地格，攻擊兩次破除。以本機登入 UID 作為記錄鍵，按「知道了」後不再自動彈出，並可用工具列「？」隨時重看。
- 戰場在尚未破除的陣眼上繪製小型準星及 `hp/maxHp` 耐久標籤；只有招式命中範圍、行動回合、體力、出手上限均允許時才顯示綠色可命中準星。這些 UI 標記不會影響角色 hit-test。
- 點選或長按陣眼顯示簡短戰術提示。移動模式點擊陣眼只顯示提示，不會錯誤自動移到陣眼；切換到攻擊後維持原有有效點擊立即施放方式。
- 新增純讀取的 `QATacticalSealTargeting`，對每座陣眼以 `QATactical.aimCells`、`skillCells`（必要時 `techniquePreview`）、`validateSkill`、`techniqueCost`、`attackLimit` 推導是否能命中與原因；不擅自更動伺服器規則、不自行估算傷害。
- 無法命中時提示「石障擋住視線」「此招式目前無法命中」「請先切換攻擊」「體力不足」「行動／出手已滿」等原因；不把 AoE 光圈涵蓋到陣眼之外的施法當作有效命中。強化技能和蓄勢技能不誤標為可直接擊破。
- 所有陣眼標記繪製於人物、靈獸及血條後方；視野縮放與手機／平板拖曳不改變格子的實際命中座標。
- 此階段做輕量提示；下一階段才開發完整陣眼情報面板、查看位置及策略資訊。
