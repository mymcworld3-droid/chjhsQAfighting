# 多 API 並行出題任務

每次 `/api/generate-quiz` 出題，先建立本輪任務計畫，再把不同任務同時交給首批最多三組不同憑證的 API。依近期題型與當次範圍，分派基本應用、逆向推理、錯誤辨析、情境建模、資料判讀、比較辨析、多步推理或概念遷移等不同任務；每個 API 都生成一題完整的單選題與解析。

## 任務邊界

- 所有任務維持同一個已選科目、年級、單元、知識點與難度。題型、作答目標與解題骨架各自分工，不能只更換數字、人名或地點。
- 每個任務有獨立 ID，普通提示與戰鬥精簡提示的題型及輸出範例一併依任務建立，避免主提示指定一種題型、附加指令又指定另一種。
- 入門與團本快答僅分派基本應用、比較辨析或單一步驟的錯誤辨析，維持一步判斷／應用，不因並行分工提高難度。
- 當題型輪替用完，後續備援任務使用新的 ID 及另一個構題切入方向。路由器依「實際呼叫順序」配置序號，避免同一憑證的備援模型重用首批任務。

## 驗證與交付

原有科目、知識點、格式、四選項唯一性、TeX、答案與解析一致性、歷史題幹及解題骨架去重照常執行。每份新生成回應另須符合本次分派的 `generation_task_id` 與 `question_form`；任務不符者不可成為首題或備用題。

最快通過驗證的結果立即交付；較晚完成的合格題目存入原有、按使用者／工作階段與範圍隔離的限量備用池。下一次請求優先取相容備用題，依新的歷史紀錄再次驗證。備用池仍會拒絕與已交付題目或其他備用題重複的題幹及骨架。

內部任務 ID 不顯示在學生題幹、選項、解析或回傳題目資料中。題型標記保留供既有能力分析使用；團本與悟道試煉仍在實際交付時簽發／保存各自的權威題目。

同時呼叫上限、逾時、單 API 路徑與整批失敗後的備援次序沿用既有設定。任務規劃由程式完成，不另外呼叫 AI；驗證失敗仍可能觸發既有重試。測試使用模擬 API 驗證同步分工及路由，未以正式 API 宣稱測得題目品質或速度改善。
