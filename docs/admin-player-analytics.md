# 管理員：玩家事件與留存分析

## 入口與部署

管理員頁新增「玩家事件與留存分析」收合區塊。所有聚合都由 Render 後端執行，瀏覽器只拿管理員驗證後的彙總值與最近 25 筆去識別事件。

- 後端需有 \`FIREBASE_A_SERVICE_ACCOUNT_JSON\`（與帳號管理 API 相同）。不需要讓瀏覽器讀取 analytics 集合。
- 新的 Firestore 集合：\`playerAnalyticsVisitors\`（匿名 Cookie）、\`playerAnalyticsPlayers\`（驗證後的 UID）、\`playerAnalyticsDaily\`（玩家每日彙總）、\`playerAnalyticsEvents\`（90 天短期事件）。
- **部署時確認 Firestore Security Rules 拒絕用戶端存取上述四個集合**；本專案目前沒有把部署用 Firestore Rules 放進版控，不能假定已設定。
- 在 Firebase Console 為 \`playerAnalyticsEvents.expireAt\` 啟用 Firestore TTL，設定 90 日清除。只有寫入 \`expireAt\` 欄位不會自動啟用 TTL。
- 在站內隱私說明揭露匿名 \`qa_analytics_vid\` Cookie（HttpOnly、SameSite=Lax、有效期一年）及其統計目的，並確認適當的告知／同意安排。
- 舊的 \`users\` 和 \`exam_logs\` 不回填：舊玩家首次被追蹤的日子**不得**冒充註冊日。玩家 cohort 以 Firebase Authentication 的 \`creationTime\` 為準，且只有在建立當日已開始追蹤的帳號才符合新玩家 cohort 資格。

## 事件與計算

| 訊號 | 何時送出 | 去重 |
|---|---|---|
| 到訪 | 每次開啟網站（未登入也記錄） | 同 Cookie 的訪客固定首訪日 |
| 會員回訪 | Firebase Authentication 狀態確定後 | 同 UID 的台灣日曆日去重 |
| \`question_started\` | 問道實際成功顯示可選答案 | 同一題沿用 event ID |
| \`answer_completed\` | 問道答題完成且需要持久化時已成功寫入；閉關選答完成；鬥法交易成功；團本伺服器確認結算 | UID + eventId，在 Firestore 交易內去重 |
| \`social_participated\` | 鬥法作答提交成功；**至少兩人**團本中伺服器確認提交成功 | UID + eventId |
| \`question_load_failed\` | 問道或延伸問道題目生成／載入失敗 | 每次失敗一事件 |
| \`app_load_success\` / \`app_load_failed\` | 已登入後修仙功能模組批次載入成功／失敗 | 每次啟動一事件 |

有效答題統計是「應用程式完成的作答事件」，不是具防作弊驗證的成績資料庫；惡意修改瀏覽器程式的使用者仍可能偽造行為事件。任何獎勵、配對或付費規則不得依賴此分析 API。

- **首題開始率**：近 7／30 日首次造訪的 Cookie 數為分母，首訪當天實際顯示問道題目者為分子。Cookie 清除／換瀏覽器會視為另一訪客。
- **首三題完成率**：指定期間新玩家 cohort，且首題開始後已過 24 小時的人數為分母；首題後 24 小時內完成至少 3 題有效作答的玩家為分子。放棄按鈕不計題數。
- **D1／D7**：分母只包含 cohort 已滿 1 或 7 日的玩家；回訪指定的第 1 日或第 7 日，即使未答題也算。使用台灣日期（UTC+8），不是登入後連續 24 或 168 小時。例：今天 10/16，近 7 日 D1 分母是 10/08–10/14 註冊玩家，D7 分母是 10/02–10/08 註冊玩家；排除尚未結束的 10/16 觀察日。
- **每週有效答題數**：最近 7 日問道／閉關／鬥法／團本事件總數，跨模式去重並顯示分項。
- **社交參與率**：最近 7 日曾成功參與多人行動的 UID／最近 7 日有回訪的 UID。附同 cohort 的「註冊首日曾參與社交 vs 未參與」D1 對照；**相關不等於因果**。
- **載入失敗率**：題目載入失敗／（題目顯示＋失敗）與功能模組批次載入失敗／全部批次啟動分開計算。無法到達登入流程的失敗無法算在模組指標內。
- 沒有合格分母時，前端顯示「—」，**不是 0%**。

## 事件一致性與效能

- D1 版本以交易保留每個事件與去重鍵，但玩家、訪客摘要只有實際統計改變時才更新；`lastAt` 代表該摘要最近變動，不再隨每次事件重寫。穩定答題階段的「題目開始＋完成」由 8 次文件寫入降為 5 次（摘要首次補齊時可能較多）。每日累計與短期事件仍逐筆記錄。
- D1 不使用 Firestore TTL。先套用 `0004_analytics_retention.sql`；已套用者不需再建新表。清理由已驗證玩家的到訪 API 在回應送出後於 Render 背景觸發，沒有瀏覽器輪詢、畫面提示或登入等待，也不使用固定 Cron。無玩家登入時不啟動清理。
- 每個 Render 程序的 A-store 共用執行中鎖與冷卻：有資料待清時至多每小時一次；D1 回報本輪刪除 0 筆時延至 12 小時後。每輪最多清除 500 筆已滿 90 天的事件，SQL 合併為一個 Workers 請求。失敗也冷卻一小時，不跟著每次登入重試；多程序／重新啟動會各自重新建立記憶體冷卻。
- 日期及 Firestore Timestamp 皆支援；不刪除玩家、訪客及每日彙總。保留刪除版本以阻止舊交易復活事件；空清理不異動版本。最近事件與到期查詢均使用分析專用索引，缺少 migration 時清理延後但不阻擋登入。
- `wrangler.jsonc` 的 Cron 清單已清空；若曾部署上一版小時排程，需重新部署 Worker 才能移除 Cloudflare 既有排程。Render 更新後即可使用登入觸發的背景清理；合併程式碼不會自動執行正式 migration 或 Worker 部署。
- 後端對事件類型、模式和 ID 設白名單；驗證 Firebase A ID Token、收件者 UID、專案及 Token 是否撤銷。管理員報表另外核對 \`users/{uid}.isAdmin\`。
- 以 UID 與事件 ID 雜湊產生事件文件 ID。在 Firestore 交易中先確認不存在，才更新玩家與每日統計。UI 同題重複渲染與網路重送不應重複累計。
- 不蒐集題目、選項、作答內容、IP、Email、UA；最近事件只展示不可逆的 UID 雜湊前 8 碼。Cookie 只由伺服器產生。
- 每次報表目前最多讀取每個主要集合 12,000 個文件，遇到上限會顯示「不完整」警語。流量變大時應改採每日聚合與定期批次計算，避免無限制讀取。
- 瀏覽器停用 Cookie、廣告阻擋器攔截分析請求、離線及網路錯誤均會使事件遺失，故此資料適合產品迭代，不宜作財務結算或考生成績證明。

## 驗收

1. 用全新無痕瀏覽器開首頁但不開始答題，首訪分母應增加一次；同瀏覽器重新載入不應再增加新訪客。
2. 開始第一題後，「首題開始」分子增加；同一題來回切頁或刷新不可重複增加。
3. 使用正式答題流程回答三題，**24 小時後**再核對首三題轉換；未滿 24 小時不可納入分母。
4. 同一測試帳號在次日及第七日回訪，即使不答題，D1／D7 也應計入對應成熟 cohort（依台灣日期）。
5. 單人團本不得算社交；多人團本提交成功、鬥法交易成功才算。
6. 讓出題 API 失敗一次、讓登入後功能模組載入失敗一次，確認兩項失敗率分別增加。
7. 用非管理員 Token、失效 Token 呼叫 \`/api/admin/player-analytics\`，分別回傳 403／401；不能讀到全站事件資料。
8. 短時間切換近 7 日／30 日，應顯示最後選取的期間及分母，不能顯示舊請求結果。
