## 1. 目標、範圍及不可妥協原則

五大目標：速度、正確性、範圍涵蓋性、人類可讀性、挑戰性。另需兼顧成本、可追溯性、隱私及穩定性。

核心流程：自然語言/圖片/選單輸入 → 教材搜尋與版本確認 → 知識點及學習邊界 → 玩家確認 → 真人試題搜尋與分析 → 知識點排程 → AI/已審核原創題/參數化題型 → 獨立驗證 → 可用題目佇列 → 答題/解析/學習足跡 → 個人化修正及補充。

**沒有預先登錄的真人參考題庫是設計前提。** 系統必須具備真實網路搜尋與來源擷取能力，不能以人工預建題庫作為啟用前提，不能把模型記憶、搜尋摘要或 AI 虛構題當真人原題。可自動建立有來源證據、依法允許保存的快取。既有 AI 題庫與已驗證原創題可重用，但不得冒充真人題。

速度靠預取、並行、快取及快速驗證，不靠放行未審核題。範圍靠版本與知識點白名單、考查深度及限制，不靠一句「不要超綱」。難度來自推理深度，不是冷僻知識、冗長敘述或複雜運算。所有 AI 生成內容均為不可信輸入，通過必要驗證才可對玩家提供。

Beta 初期只作用於獨立學習入口，並沿用既有答題、解析、學習足跡及授權適用的共用模組；不自動切換問道試煉等模式的出題來源。未來跨模式接入另行授權。初期驗收重點為高二化學、物理、數學，但架構不得寫死為三科或某出版社；其他年級/科目在有證據且通過對應驗收後才宣稱支援。

## 2. 玩家體驗與介面

### 2.1 入口與狀態
- 現有「專注學習」後方新增「自適應學習引擎 Beta」；位置以第 0 階段實際 UI 結構為準，不擅自加到全域導覽或另開頁籤。沿用主頁色調與元件，不製作不必要的外框、不堆疊說明。
- 建議總開關 `ADAPTIVE_LEARNING_ENGINE_BETA`（實際命名依專案慣例），伺服器與客戶端一致；開發/測試可啟用，正式環境預設關閉，最終驗收後才按規則開放。停用時安全返回既有入口，保留學習紀錄。
- 初次進入：自然語言輸入、既有範圍/科目年級選單、上傳課本目錄或老師公布範圍（若既有安全上傳管線可用）、最近範圍、錯題複習。圖片辨識需確認低信心文字，不將原始私人照片交給公共搜尋引擎。
- 顯示真實狀態：正在辨識範圍、確認教材、搜尋真人試題、題目準備中、可開始、部分範圍尚未確認、搜尋失敗；不顯示虛假百分比。
- 範圍確認頁：章節預設收合、已確認觀念預設勾選、未確認預設不出題；章節/觀念可單獨取消、自然語言追加排除限制、顯示教材版本/來源、儲存範圍、快速套用。部分選取狀態、撤銷、鍵盤、直橫式均需測試。
- 答題頁：沿用既有公式、圖片、表格、白板、助手（若存在且支援）、批改與解析。答案送出前不得由 API 或客戶端 payload 洩露；答後才顯示解析、觀念、難度、回報入口。允許下一題即取即用，不必等全批完成。
- 進度頁：顯示章節涵蓋（已練習/有效觀念）、掌握度（含樣本數與信心）、待複習、尚無參考資料的觀念。不要把生成、排隊、展示或答對混為同一個指標。

## 3. 系統分工與資料流

1. Scope Parser：自然語言解析、否定語意、跨冊範圍、教材版本候選、圖片/文字正規化。
2. Curriculum Resolver：真實網路檢索、來源比對、章節與版本關係、觀念及學習深度證據。
3. Scope Manager：範圍版本、玩家確認、知識點白名單、排除規則、先備工具、個人修正。
4. Reference Retriever/Analyzer：真人試題搜尋、擷取、來源驗證、題型分析及合法快取。
5. Learning Scheduler：範圍配額、掌握度、間隔複習、難度與題型多樣性。
6. Question Generator：在排程指定的考點、題型、難度、參考結構下生成新題；已驗證題及參數化題也是來源。
7. Quality Gate：程式驗證、獨立解題、語意/範圍/挑戰性審核、重複性檢查。
8. Question Queue：預取、重試、併發限制、優先級、版本隔離、獨立入列、耗盡降級。
9. Learning Feedback：批改、掌握更新、回報、撤銷、全域題目停用、觀念覆蓋分析。
10. Observability/Operations：追蹤、成本、來源健康、SLO、管理端與功能開關。

伺服器負責可信資料、搜尋憑證、答案、授權、排程、計分、審核狀態及佇列。客戶端只負責顯示與互動。不依賴前端計時器或瀏覽器背景活動來完成必要生成/審核工作；使用符合現有部署方式的持久工作機制，若平台不支援常駐 worker，採持久工作表與受控觸發方式。

## 4. 範圍選擇引擎

### 4.1 需求解析
結構化欄位至少包含 educationLevel、grade、subject、publisher、curriculumEdition、bookScheme、start/end section、explicitIncludes、explicitExcludes、intent、preferredDifficulty、locale。保留原始輸入供使用者核對，公共搜尋只送出必要教材詞，不送個資。

支援跨冊、起訖皆包含、單一觀念、整章、整冊、多科、錯題複習、增量修改。冊別命名要特別處理必修是否列入冊序、選修Ⅰ/Ⅱ/Ⅲ與第三冊的差異。不可按字面數字自動對應。版本歧義優先透過資料解決；仍有實質差異才提供簡短候選讓玩家確認。

### 4.2 教材檢索與驗證
來源優先：玩家提供的課本/老師範圍（用來判定個人邊界）→ 出版社官方目錄/試閱 → 官方課綱與學校課程計畫 → 公開教師講義/可信教材。課綱只能證明學段大範圍，不可單獨證明出版社章節歸屬。試題來源可補充考查方式，但不能反向擴張學習邊界。

並行搜尋不同冊別/章節，實際讀取頁面或 PDF；檢查版本、章節順序、頁碼/段落、資料日期，必要時交叉驗證。重要來源冲突不得用多數決或模型信心分數取代證據。每一知識點標示 verified / uncertain / excluded，保留來源及證據定位。低可信、付費牆、無法擷取、掃描辨識不清等情況不得假裝確認。

### 4.3 知識點資料模型
教材版本 → 冊別 → 章 → 節 → 主要觀念 → 細部觀念 → 考查方式（概念辨識、圖表判讀、計算、實驗設計、整合、遷移）。採穩定 ID、別名映射、版本關聯、跨版本對應但不強制合併。

每一 concept 至少記錄：id、name、parentId、editionId、sectionId、aliases、allowedSkills、excludedSkills、prerequisiteTools、depthLimit、evidenceRefs、status、revision。每一 scope 保存 scopeId、ownerId、revision、confirmedConceptIds、assessmentModes、personalExclusions、editionIds、resolutionStatus、createdAt。

例：平面向量內積允許二維座標/夾角計算；排除三維內積；基本代數可作為先備工具但不能獨立考查。高二化學例「南一第三冊 3-1 到第四冊 1-2」須先查明實際版本，不能將前面對話的示範章節直接當官方資料。反應級數、平衡常數等細部深度（例如 Kp/Kc 轉換、半衰期）要有對應教材證據才啟用。

### 4.4 確認、變更與版本一致性
只允許 confirmed/verified 觀念成為正式出題目標；玩家明確確認自訂範圍時標示為使用者自訂，不能冒充出版社已驗證資料。未確認概念可繼續檢索並提示新增，不能默默加入已確認範圍。若已有可靠的部分範圍，可經玩家同意先練習部分。範圍完全不明時不出題。

每次確認/修改產生新 revision；生成前、審核後、入列及發題時驗證 revision 和所有考查點。舊工作可取消或保留為不屬於玩家佇列的合法共用候選，僅在重新比對後可用。不能在玩家取消觀念後仍派發該觀念。作答中的題若受變更影響，給跳過/更換且不因系統錯誤扣分；既有歷史紀錄保留。

## 5. 真實網路檢索（不需人工登錄）

### 5.1 服務能力
第 0 階段盤點現有模型與伺服器是否真的支援網路搜尋。建立可替換 SearchProvider、FetchProvider、DocumentExtractor 介面。使用合法可用的搜尋服務或模型提供的真實搜尋工具（核實其 API 能力及使用條款）。普通文字生成 API 不等同搜尋。API 密鑰只放伺服器環境變數；遵守速率限制與配額，不透過多金鑰繞過限制。

搜尋語句按觀念生成，而非只查玩家原句。例如「高二化學 初速率法 段考 試題 答案 PDF」、「高中化學 動態平衡 圖表 試題」。可並行查相同出版社、同年級、同觀念不同版本、大考中心、公開教師題目；搜尋來源可以擴大，實際考查範圍不能擴大。

### 5.2 真實來源與擷取
優先學校官方試題、大考中心、出版社公開資源及可信教師教材。擷取實際文件，HTML 主內容、PDF 文字、表格、公式、頁面圖像；掃描檔才視需要 OCR，辨識不可靠的題不使用。比對題號、圖表、選項及答案檔；答案缺失時標示 unknown，不自行填成官方答案。只找到題號或摘要不算已取得參考題。不能確認原題出處或真人來源的資料標記 unverified，不計入真人參考。

來源紀錄：sourceId、canonicalURL、documentTitle、publisher/organization、year、page/locator、retrievedAt、contentHash、sourceType、humanProvenanceStatus、extractionQuality、license/usePolicy、answerEvidenceStatus。區分 official/human-attributed/unknown/AI。保存合法證據或必要摘要，不公開宣稱網路公開即有重製授權；不得繞過登入、付費牆、robots 或存取限制。不授權保存原文時僅保存可合法重用的抽象考查結構及來源；無法合法利用則跳過。

搜尋與擷取要防 SSRF：僅允許受控 http/https 公開來源，阻擋內網/IP 及重導向至內網、限制檔案大小、類型、時間、頁數及解析資源；來源網頁中的指令、腳本、提示詞注入都當作資料而非指令。禁止來源要求外傳憑證或執行任意指令。對客戶端輸出做 HTML/公式安全處理。

### 5.3 真人題型分析與選取
擷取後建立 ReferencePattern：主要/次要 concept IDs、考查目的、題幹結構、資料呈現、解題步驟、干擾選項的錯誤觀念、難度證據、來源 ID、使用限制、品質狀態。難度若有實際答對率可記錄樣本與年份，沒有就標註估計。

每次 AI 出題選取約 2–3 個同觀念的高相關且不同結構參考；按教材匹配、來源可信、考查方式相符、近期未用、授權排序。不足時使用實際可得的數量，不捏造。僅有一個可靠範例也可出題，但標示參考不足並持續找不同結構。

生成題需有 provenance：web_grounded_original（有可核驗真人參考）、verified_original_no_reference（無真人參考但已驗證原創）、parametric_verified、licensed_original（有明確授權的原題）。不得將後三種來源統計成有真人參考的新題；無參考原創不得假冒段考。初期真人參考充足的觀念優先使用 web_grounded_original；缺少參考時，只有符合範圍與品質門檻的既有題/模板可作明確標示的過渡，仍無可用題就告知等待或選擇其他已確認觀念。

### 5.4 快取與成本
共用快取鍵需包含教材版本、concept ID、搜尋/解析版本、來源指紋及授權狀態；搜尋結果/失敗短期快取、文件和題型較長期快取，具 TTL、失效及來源撤回機制。初始建議搜尋快取 7 天、負快取 10–30 分鐘、教材驗證快取 30 天（可配置，須服從來源限制與實測）。同一觀念同時有多個玩家搜尋時使用 single-flight 合併工作。不因某玩家排除個人內容而改全域教材。

## 6. 知識點排程與涵蓋性

排程器由程式選定目標 concept、assessmentMode、difficulty、questionType，AI 不自行決定考什麼。初始配額：40% 尚未或少量練習、30% 弱點、20% 綜合挑戰、10% 間隔複習。無合格候選時依規則重新分配；以滾動視窗實施，不要求每四題嚴格湊比例。短回合不保證完整涵蓋，長時間也不能讓低權重觀念飢餓。

每個觀念維護 presentedCount、attemptedCount、correctCount、lastSeenAt、lastAttemptAt、dueAt、mastery、confidence、referenceAvailability、inFlightCount。出題時保留名額，入列不算涵蓋；真正展示才算曝光，完成有效作答才算練習。多觀念題只計實際獨立被考查的目標，不將附帶背景觀念虛增覆蓋率。

以 coverageDebt + weakness + spacingUrgency + diversityBonus + challengeFit - repetitionPenalty 作為可配置的優先度；硬性規則優先於分數。對每個未排除、已驗證且有可用題的觀念設定最晚服務窗口（例如每 C×2 次有效作答內至少練一次，C 為可用觀念數；依實際難度及題型調整）；無可用題列出阻礙並提高檢索優先級。綜合題的所有目標與必要先備均須符合範圍。

提供全範圍均衡、弱點複習、考前綜合等模式，但預設自動混合。使用者手動指定難度可限制自適應範圍。

## 7. 出題與挑戰性

### 7.1 三種生成路徑
- 已審核題池：重用符合 scope revision/觀念、難度、授權及驗證版本的題；優先未見題。
- 參數化模板：人工或可信設計的模板、可重現種子、合理數值、選項與解析由確定性求解驗證。少量用於低延遲和特定計算題；禁止只換數字造成重複。
- AI 網路參考原創：輸入明確考點、學習深度、排除限制、考查方式、合法的參考結構及玩家近期題型摘要。要求原創、不複製原題、不混用未核實答案、不引用未提供的來源。輸出嚴格 schema（沿用既有題目格式並擴充 metadata）。

每次請求 1–2 題，優先 1 題以便獨立入列；可用批次降低開銷但不可因同批慢題阻塞已合格題。模型輸出錯誤最多有限重試（初始 1 次修復），之後換參考/題型或淘汰。

### 7.2 題目契約
至少保留 questionId、schemaVersion、language、type、stem、options、answer、solution、conceptIds、primaryConceptId、assessmentMode、difficulty、prerequisiteSkills、sourceKind、referenceIds、structureFingerprint、validationStatus、generatorVersion、validatorVersion、scopeCompatibility、createdAt。圖表應使用可驗證資料與既有安全渲染元件，表格欄位、單位及圖軸都必須完整。正式 API 給玩家不含答案、解析、審核內部資訊，答後按既有權限顯示。

### 7.3 人類可讀性與題型
用台灣教材術語、先給必要條件再提問、明確指出單/多選或計算；每個干擾選項對應具體錯誤觀念。禁止資訊不足、雙重否定混亂、未說明假設、與題意無關的故事、人工堆砌生僻詞。素養題以實際情境、文章、實驗或可信時事資料為基礎，考學科運用而非單純閱讀理解；涉及時事應附來源且不得杜撰。數學/物理/化學圖表、概念判斷、實驗設計、計算與整合應輪替。

難度 1–5：基礎辨識、單觀念應用、多步推理、跨觀念整合、陌生情境遷移。調整推理步驟及觀念整合，不以超綱或冗長運算提高難度。初始難度分配可為 10/30/35/20/5%，依觀念掌握度調整；正確率 65–80% 是暫定體驗目標，不是強行維持的 KPI。考試模擬模式保留指定難度。

## 8. 品質驗證與題目治理

### 8.1 多層驗證
A. 程式快速驗證：schema、答案格式、選項數與唯一性、公式/單位、數值界限、必要資料、concept 白名單、版本及授權、精確去重。涉及數學/物理/化學的可計算題，使用可重現的確定性求解或約束驗證，優先沿用伺服器現有語言與數學庫，禁止執行模型生成的任意程式碼。

B. 獨立盲解：另一個獨立模型請求只接收題幹、選項與必要資料，不提供原作者答案或解析。解出正確選項/數值、必要假設並檢查所有選項；多選必須比對完整集合、數值依題型容許誤差/單位規則。

C. 品質與範圍：獨立檢查實際解題所需觀念（不信任生成標籤）、語意、條件完整、答案唯一性、可讀性、干擾項品質、挑戰性及參考結構相關性。B/C 可並行。初始採 1–5 分 rubrics，各必要維度至少 4，重大範圍/正確性錯誤一票否決；門檻由實測校準。

D. 交叉比對：A/B/C 全部必要條件通過才合格。AI 答案一致不代表必然正確；爭議或不確定即隔離，能修復則重新跑必要驗證，不行就丟棄。審核超時不等於通過。已驗證題可重用，驗證版本/題幹/答案/來源/教材變更或回報時重新判定。

E. 人工抽樣及回報：定期抽樣真實玩家體驗、按科目與難度分層；可讀性、人類風格和難度需人評，不能只用 AI 自評。回報後由獨立流程確認，保留審核記錄及修復版本。

### 8.2 去重與題目多樣性
精確 hash、正規化文字、選項排序不敏感指紋、結構指紋（考點、考查方式、推理圖式、資料呈現、情境）、必要時語意相似度。區別故意的錯題強化；即使文字數字不同，若解題結構過近就限制近期重現。預設最近 20 題避免精確重複、最近 5 題避免無意義的同結構連續出現（可依候選數量與觀念複習需求調整，任何放寬應可追蹤）。同一真人來源不可大量產生僅換數字的近似題。

## 9. 低延遲、佇列與故障處理

### 9.1 真正的非同步流水線
玩家輸入範圍 → 解析、教材搜尋並行；章節證據確認後立刻搜尋對應真人題，並可準備候選題。玩家尚未確認前僅暫存，不能正式發放；確認後重新比對 scope revision。第一道題驗證完成可直接入列，不等待同批全部完成。玩家答題期間由遊戲伺服器持續補充。

初始建議：可開始時至少 1 道已驗證題（目標 3 道）；正常維持 5–8 題、低水位 4、上限 10；每玩家 3–4 個生成併發工作為可調上限，搜尋併發另設限制，全服總量依供應商配額、伺服器容量及預算調整。不能把每玩家併發直接乘全服無限擴張。取題目標 P95 伺服器端 ≤200ms（暖佇列），另量測端到端、首次冷啟動、暖啟動及各階段延遲。

### 9.2 工作狀態與一致性
queued → fetching/generating → validating → ready 或 rejected/failed/cancelled；ready → leased/presented → answered/skipped/expired。用持久工作狀態、owner/session/scope revision、idempotency key、lease/expiry、重試次數、優先序及 traceId；入列及發題用原子操作/交易避免重複。多裝置並行不重複發題或計分。頁面關閉/斷線時可取消個人預取；已合法驗證的共用候選可保留。答題提交冪等，失敗可重試，不重複計分或獎勵。

### 9.3 降級及成本
搜尋失敗 → 合法且仍匹配的快取；生成失敗 → 已驗證未見題/模板；候選不足 → 優先其他已確認觀念並顯示欠缺；全無合格題 → 顯示真實準備中/重試/返回舊模式，不默默切換超綱題或放行未審核題。API 429/5xx/timeout 採有限退避與 jitter、熔斷、每使用者及全域限額、每日預算及快取命中策略。不可用測試假搜尋代替正式服務。

## 10. 自適應學習與玩家回報

沿用既有學習足跡的使用者與權限規則；避免重複記帳。以有效首次作答更新觀念掌握，記錄題目難度、答對/錯、提示、訂正、跳題及樣本數；作答時間只是輔助（不能把斷線、裝置慢或無障礙需求當學習弱點）。

初始可採平滑模型：每觀念 Beta(2,2) 先驗，首次有效作答更新 alpha/beta，掌握估計 alpha/(alpha+beta)，同時保存有效樣本量；難度及提示效果另做分層或有界權重，低樣本不激烈調整。將來資料充足才考慮 IRT/BKT，並做校準。綜合題沒有細項答案時不得推斷每一觀念都已掌握；以低權重更新或後續單觀念診斷。

間隔複習初始建議 1/3/7/14 天，錯題可在同次練習間隔數題再考不同結構，避免立刻重複。難度升降需看同觀念近期有效樣本，限制每次最多一級、避免震盪。所有數值可配置，需真實資料校準。

玩家回報分流：答案有誤、題意不清、公式/圖表異常、超過學習範圍、太簡單/太難、太重複。超綱可選 AI 識別的具體觀念或輸入限制，由玩家確認後即更新個人 scope revision，撤銷/重新啟用時再更新；不直接修改全服資料。若教材本身有錯，另走來源核對與全域版本修正。確認有誤的題立即停用、取消待發、追查同模板及生成版本，補償/作答紀錄更正使用既有規則與冪等性，錯題不得算成玩家弱點。不能在未確認前宣稱補償已入帳。

## 11. 資料、API、隱私及維運

建議邏輯實體（名稱依現有資料層）：curriculum_editions、curriculum_sections、concepts、scope_revisions、source_records、reference_patterns、question_items、question_reviews、generation_jobs、question_queue、learning_attempts、concept_mastery、question_reports。優先重用現有 schema 與共用函數，新增欄位須向後相容；不可強制遷移或刪除舊玩家資料。共用教材/題型與個人範圍/紀錄隔離，索引涵蓋 concept/edition、scope revision、job status、owner、fingerprint 等。

API 行為契約（不指定實際 URL）：resolveScope、getScopeResolution、confirmScope、reviseScope、getReadiness、getNextQuestion、submitAnswer、getLearningProgress、reportQuestion、undoScopeExclusion。沿用既有認證、權限及防濫用；所有個人資料按帳號隔離，伺服器驗證 owner/role；前端不得指定正確答案、掌握度、審核狀態、獎勵或直接寫入共用題庫。

不把姓名、班級、身分資訊、私人照片或完整個人學習紀錄送給公共搜尋；模型只得到完成任務所需的最少資料。原始上傳限制存取和保存期限，日誌遮蔽密鑰與個資；來源內容與使用者輸入都不可信。遵守既有帳號刪除/資料保留政策及未成年使用情境，學生資料不得跨帳號外洩。

監控：scope resolve latency、search success、fetch/parse success、reference coverage、generator latency、review pass/reject、queue starvation、serve P95/P99、每題成本、快取命中、回報率、重複率、跨版本阻擋數。以 traceId 串起 scope → reference → question → review → attempt，日誌避免保存不必要原文。管理端提供來源停用、題目隔離、快取清除、限額及 feature flag 控制（依現有角色授權）。

## 12. 驗收標準與測試設計

以下為初始目標，不是現有遊戲實測結果。所有百分比需同時報告分母、樣本數、科目/難度/版本分布與限制；不足樣本不能宣稱達標。

| 目標 | 初始驗收標準 |
|---|---|
| 速度 | 暖佇列取題 P95 ≤200ms（伺服器端）；另測端到端、冷範圍首次題與佇列耗盡。已驗證暖範圍解析 P95 ≤1s 為初始目標；冷搜尋延遲先建基線再訂可達 SLO。 |
| 正確性 | 人工盲解抽樣正確率目標 ≥99%；答案洩漏、錯誤題放行、跨帳號資料外洩為零容忍；樣本不足如實標記。 |
| 範圍精準 | 教材/章節對應 ≥99%；超綱率 <1% 為統計品質目標；任何已知超綱不得放行，版本混用及排除失效測試必須零失敗。 |
| 範圍涵蓋 | 對有可靠教材基準的樣本，細部觀念涵蓋率 ≥95%；所有啟用觀念可追溯；排程長程測試無無故飢餓。 |
| 真人參考 | web_grounded_original 的來源可驗證率 100%；各範圍另報有真人參考的觀念比率與實際供題比率，不把無參考降級當成功；冷啟動至少驗證真實網路來源。 |
| 人類可讀性 | 人工 rubric 平均 ≥4.5/5；重大語意缺漏零容忍；至少兩名評閱者或清楚標記單人評閱限制。 |
| 挑戰性 | 自適應練習的群體正確率目標 65–80%（需有足夠樣本），難度層級與推理深度人工抽查一致；不得故意出錯來調整正確率。 |
| 多樣性 | 非刻意複習的近期結構重複率 <5% 為初始目標；區分結構、文字與原題重複。 |
| 成本/穩定 | 暖快取與冷搜尋成本分開統計，配額與全域上限可驗證；API 失敗/斷線/重送/跨裝置不造成未驗證題或重複記帳。 |

測試矩陣：單元（解析、版本、排程、求解、審核門檻）、整合（搜尋/擷取/快取/佇列/回報）、契約（API/schema/權限）、E2E（冷/暖範圍、玩家修改、下一題、回報、恢復）、壓力（多玩家/429/超時/worker 重啟）、安全（SSRF、提示詞注入、XSS、答案洩漏、IDOR）、手機/平板/桌機直橫式、舊功能回歸。CI 可用明確標記的 fixture 取得可重現性；真實網路驗收另執行且記錄來源，不把 fixture 當真人。

核心實戰情境：A. 高二化學南一第三冊 3-1 到第四冊 1-2（跨冊、同名版本歧義、排除未學平衡內容）；B. 高二物理萬有引力與克卜勒定律（排除衛星變軌）；C. 高二數學平面向量內積（禁止三維）；D. 上傳老師範圍及跨科；E. 選範圍後立刻更改且舊生成仍回傳；F. 全新範圍無快取、只有真人資料稀疏來源；G. 模型答案不一致、審核超時；H. 玩家回報錯題後撤銷排除；I. 舊專注學習、戰鬥與教師模式完全未受影響。

## 13. 分階段開發（第 0–26 階段，共 27 階段）

每階段除下列專屬驗收外，均需跑相關新增測試與既有必要回歸、更新進度文件；依執行契約處理提交及 CI。不得在依賴未就緒時跳過，允許拆子階段。

### 第一批：基礎、隔離及可追蹤性（0–3）

**第 0 階段｜最新 main 盤點與架構基線**  
讀取專案樹、README/測試/CI、專注學習入口、範圍選擇、出題提示詞、參考題檢索、題庫、審核、學習足跡、回報、API/provider、資料層、部署能力。確認真實搜尋服務與憑證是否可用，記錄現有問題、重用清單、檔案路徑、依賴圖、基準測試及 SHA。將本規格及進度文件存入 repo。驗收：架構盤點基於實際程式、基準測試狀態明確、未重寫功能。若已有失敗，記錄並先修復阻塞相關工作的回歸（可拆 0A）。

**第 1 階段｜Beta 入口及功能開關**  
在專注學習之後新增符合既有風格的獨立入口，Beta 標籤、路由/狀態殼、伺服器開關、關閉時安全行為。驗收：開關、權限、位置、舊入口與導覽不變；手機及平板基本測試。

**第 2 階段｜共用資料契約及隔離**  
定義 scope、concept、source、reference、question、job、review 等 schema 及版本；相容舊題格式；伺服器權限、私有/共用資料隔離；資料遷移及回滾策略。驗收：舊資料讀寫、schema 測試、無跨帳號存取、無未審核題暴露。

**第 3 階段｜搜尋 Provider 與安全擷取基礎**  
接真實搜尋介面、伺服器憑證、受控 fetch、超時/配額、來源檢查、trace。驗收：可用時執行真實搜尋與實際擷取，測 429/timeout/SSRF；無憑證則標記阻塞，不把 mock 當完成真人檢索驗收。

### 第二批：教材理解與範圍選擇（4–8）

**第 4 階段｜自然語言與版本解析**  
解析跨冊、否定、指定年級/科目、增量限制；支援歧義候選；輸入 schema 與測試。驗收：三個核心學科案例、不同冊序、單/多科、非自然語言垃圾輸入均正確處理，不捏造版本。

**第 5 階段｜教材搜尋與章節驗證**  
出版社/學校/可信教材實際擷取、證據定位、版本比對、跨冊順序、衝突及不確定狀態。驗收：冷範圍來源可追溯，缺證據不得自動確認，測跨版本同名與跨冊。

**第 6 階段｜階層式知識點與邊界**  
知識點 ID/別名、細部考查方式、允許/禁止深度、先備工具、證據、驗證狀態；教材快取。驗收：平面/三維向量、化學未學內容等精確排除，無不明觀念被預設加入。

**第 7 階段｜範圍確認介面與持久版本**  
收合章節、部分勾選、排除文字、未確認提示、儲存/重用/撤銷及 scope revision。驗收：手機鍵盤、直橫式、取消觀念、舊工作失效、共用與個人隔離。

**第 8 階段｜圖片/老師範圍及增量解析**  
安全上傳與圖片辨識（若缺能力先明示阻塞）、低信心確認、多科及錯題範圍入口。驗收：照片不進公共搜尋、手動確認低信心、教師指定範圍優先、來源衝突處理。

### 第三批：真人網路試題檢索（9–12）

**第 9 階段｜知識點查詢規劃與並行搜尋**  
同出版社/同年級/同觀念逐級搜尋；優先官方來源，來源評分、去重、有限併發。驗收：零預置真人題庫的冷範圍能找到可核查候選，擴大搜尋不擴大考試範圍。

**第 10 階段｜真人文件擷取及證據追蹤**  
HTML/PDF 解析、必要圖表、公式、題號/答案對應、授權與真人來源分類。驗收：實際讀取文件，缺頁/缺圖/未知答案正確標示，不用搜尋摘要冒充原題，安全測試通過。

**第 11 階段｜真人題型分析與檢索排序**  
抽象考查結構、干擾觀念、難度與考點；每題檢索 2–3 個相關不同結構的合法參考。驗收：跨綱參考不被用於生成、無來源不冒充真人、抽樣人工檢查分析品質。

**第 12 階段｜來源快取與自動累積**  
版本化快取、single-flight、TTL、負快取、撤回/失效、管理端可追蹤。驗收：冷/暖對照、多人相同查詢合併、授權或版本變更不再取用失效資料，不需人工登錄。

### 第四批：排程、出題與品質（13–18）

**第 13 階段｜知識點涵蓋排程器**  
40/30/20/10 初始配額、防飢餓、考查方式輪替、曝光/作答分離。驗收：長程模擬、稀疏題庫、跨觀念與已排除觀念測試。

**第 14 階段｜真人參考引導的 AI 出題**  
重構提示詞及 schema，指定考點、限制、難度、參考結構，原創與 provenance。驗收：高二化學/物理/數學實際樣本，來源可追溯、無複製或假來源、題幹與解析品質抽查。

**第 15 階段｜已驗證題池與參數化引擎**  
重用已合格題、可靠計算模板及確定性求解，至少各核心科目示範題型（實際範圍驗證後選定）。驗收：大量種子測試、合法數據、唯一正解、無任意程式執行；模板不能冒充真人。

**第 16 階段｜獨立盲解及程式驗證**  
格式、公式、選項、答案、數值、盲解交叉比對及隔離。驗收：注入錯答案、多解、缺條件、單位錯、模型 timeout，皆不得通過。

**第 17 階段｜人類可讀性、範圍及挑戰性審核**  
實際考點提取、深度及先備限制、語意/干擾項 rubric、五級難度，與盲解並行。驗收：超綱、冗長、歧義、假素養與難度不符的負面案例；人工抽樣記錄。

**第 18 階段｜題目結構去重及審核題治理**  
題目指紋、語意/結構相似、重複策略、驗證版本、來源撤回與隔離。驗收：換數字的重複題、故意錯題複習、撤回後不得發題。

### 第五批：即時出題與自適應學習（19–23）

**第 19 階段｜持久工作佇列與版本隔離**  
工作狀態、lease、冪等、原子領題、重試及取消。驗收：多裝置、斷線/worker 重啟、過期工作、scope 修改不派發舊題。

**第 20 階段｜並行預取與效能降級**  
選範圍即準備、首題獨立入列、低/高水位、全服配額、熔斷及降級。驗收：暖/冷延遲、多人壓力、所有 API 失效時仍不發未審題；記錄成本。

**第 21 階段｜答題介面與學習足跡接入**  
即時領題、批改、解析、下一題、既有學習功能、進度顯示，避免答案提前暴露。驗收：完整端到端、手機/平板、重送不重複記帳、舊模式不受影響。

**第 22 階段｜個人掌握度、弱點及間隔複習**  
平滑掌握度、樣本信心、難度調整、錯題變式、到期複習、覆蓋率。驗收：低樣本/提示/跳題/綜合題的合理更新、難度不震盪、各觀念不飢餓。

**第 23 階段｜回報、補償及動態範圍修正**  
超綱/錯題等分流、個人 revision 更新、待答清理、撤銷、獨立回報審核、全域隔離及既有補償規則。驗收：精確排除三維而保留平面、回報不污染全服、補償冪等、錯題不傷掌握度。

### 第六批：品質、效能、安全與正式 Beta（24–26）

**第 24 階段｜端到端實戰與人評品質**  
冷啟動真實網路來源、暖啟動、三科完整流程、多種範圍與失敗案例；人工盲解、閱讀品質、涵蓋性、難度及多樣性報告。驗收：公開記錄樣本/分母/來源及不確定性；未達門檻回到對應階段修正，不自我核准。

**第 25 階段｜效能、安全、跨裝置與回歸**  
壓測、成本、429、惡意網頁、SSRF/XSS/IDOR/答案洩漏、資料保留及部署/回滾演練；手機/平板/桌機與舊玩法回歸；補足所有 CI 失敗。驗收：必要測試全綠，關鍵安全缺陷為零，監控與停用開關可用。無真實瀏覽器或負載能力必須標記未驗證。

**第 26 階段｜正式開放自適應學習引擎 Beta**  
核對所有前置驗收與最新 main CI；僅在必要門檻及實際搜尋服務/部署配置可用、無阻塞時啟用 Beta（可先採受控玩家群，再按實測擴大；保留關閉能力）。更新功能說明、版本/靜態資源表（若專案有）、進度與回滾指引，驗證發布後 CI 及實際入口。驗收：位置在專注學習後、Beta 可用且可停用、真實來源與題目端到端、舊功能正常。未達條件維持關閉，提供「繼續修正最終驗收」而非宣稱發布。正式版 GA 與跨模式替換不在本計畫。
