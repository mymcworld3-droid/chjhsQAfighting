# 副本 × 問道試煉：操作一致性驗收表

目標：副本 PvE 的戰場操作以 `public/cultivation/tactical-combat.js` 與 `public/styles/tactical-quarter-controls.css` 的問道試煉為準。僅保留三項設計差異：(1) 無結束回合；(2) 答題充能無每回合次數上限；(3) 蓄勢效果以六次成功施放的體修攻擊計算。

## 此次程式調整

- [x] 同一幾何的左右四分之一圓；右輪內層行動、外層技能同心扇區，含可拖曳指示塊、技能圖示、技能消耗及滑動定位。副本樣式鏡像自問道試煉 CSS，並有自動化檢查。
- [x] 左圈直接點擊答題，伺服器體力**最高 10 點**，十段環每段 1 點；正確 +4、錯誤 +1，沒有每回合充能限制。舊 100 體力房間也統一正規化到 10。
- [x] 移動模式點地格直接尋路，送伺服器逐格驗證的路線交易；每格扣 1 體力。WASD 單格移動仍保留。
- [x] 攻擊模式點地格／敵人直接施放所選功法或普通攻擊；不需先點一下選敵，再另外找技能按鈕。
- [x] 移動灰格、攻擊紅格／突進金格預覽；畫在角色與怪物之下，伺服器仍判定真正合法範圍。
- [x] **地圖不允許拖滑、雙指縮放、滾輪縮放及鍵盤平移**；只有點選地格操作，長按查看靈獸資料。右側行動圓盤依然可滑動選擇招式。
- [x] 右圈技能可顯示蓄勢剩餘層數，受六次體術減耗影響的扇區顯示金色，護盾與多人同步邏輯維持原樣。
- [x] **角色在每次畫面繪製與多人狀態同步時都處於戰場畫布正中央**，包含不規則地圖邊界和手機旋轉；離開地圖的部分填入背景，不強制把角色推離中心。
- [x] 與問道試煉相同的頂部標題、左右四分之一圓樣式；移除副本舊的縮圖、地圖放大縮小工具列與底部狀態欄。
- [x] 結束回合扇區不存在，不產生任何回合制操作。
- [x] 舊體力副本 API 保留；新 `move-route` 由伺服器認證、碰撞檢查、扣體力及序號防重送。

## 尚未宣稱與問道試煉完全一致

- [ ] **題目操作**：副本仍以 `dungeon-quiz-panel.js` 處理個人答題，尚未直接共用問道試煉的 `QATrialQuestion` 全套題頁，包括白板、問道助手、超綱／錯題回報、訂正學習與學習足跡的完整工具。此部分不能僅換 CSS，必須接上副本獨立題目票據及回報後端，避免影響正式學習紀錄。
- [ ] **戰鬥動畫**：副本使用 `dungeon-map-painter.js`，而非 `TacticalRenderer`，目前技能效果、走路動畫與攻擊過場未達問道試煉的演出完整度。不能直接交換狀態格式而不驗證即時 AI、多人同步與碰撞計算。
- [ ] **手機／平板／多人實機驗收**：新增項目已做程式與模擬測試，尚未從實際 Render 測試站逐操作驗收。
- [ ] **共用模組維護**：兩者目前共用形狀與操作契約，但問道試煉仍保留原始裝配流程；日後應再進一步抽出同一套 UI 控制器，避免分岔。

## 不可回歸事項

1. 伺服器與前端體力一律 0–10，不得再調成 100；單格移動 1、普通攻擊 2、答對 +4、答錯 +1。必須以伺服器房間的體力、招式、蓄勢層數、角色／靈獸座標為唯一戰鬥依據。
2. 點地圖不能再變回「只選目標、不執行」，且長按不能誤觸攻擊。
3. 地圖**完全禁止拖曳與縮放**；右側扇區拖滑仍要有效，且不得重複執行點擊。
4. 倒地／體力不足／目標無效應顯示清楚原因，不蓋住地圖中央。
5. 未受蓄勢影響的技能不得變金，受影響技能即使尚未指定目標仍要金色。
6. 不得在同一按鈕重複觸發兩種控制路徑；不可複製服務端的傷害或配息／獎勵狀態。
