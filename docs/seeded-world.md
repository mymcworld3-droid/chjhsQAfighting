# 種子大世界與模擬器

`grid-world` 現在使用 1000 × 1000 地圖。正式世界與模擬器共用 `public/world/world-core.js`；相同種子、生成版本與座標會得到相同地形與物件，與區塊載入順序、登入次數無關。原本墨金主題、五鍵導覽和橫式 16:9／直式 9:16 外框保留。

## 使用模擬器

開啟 `/world-simulator.html`；也可以下載 `public/world-simulator.html`，直接用瀏覽器離線開啟。單檔已內含生成器、樣式、操作程式和 Worker，不需要帳號或網路，也不會連接正式遊戲 API。

- 輸入任意種子或產生隨機種子，查看一百萬格的世界。
- 一次比較四個種子，點選比較卡載入該世界。
- 切換地貌、怪物等級、礦脈資源、秘境結構圖層；拖曳平移、滾輪或按鈕縮放。
- 點格查看座標、區塊、地貌、物件、等級與礦脈長度；「問道宗」定位中央出生點。
- 測試鋪路、架橋、放置岩壁、改變水域或還原地格。
- 匯出／匯入種子與變更 JSON；另外可匯出 1000 × 1000 PNG。變更 JSON 不含百萬格基底。

統計包含海陸比例、秘境／結構／怪物／礦脈數量、八個等級帶、主要陸塊數量和宗門可步行範圍。主要陸塊統計忽略小於 16 格的碎片；步行連通性不計算乘舟交通。

## 預設種子的內容

預設種子是 `qingyun-2026`；生成版本 `qingyun-seeded-v2`。出生點固定在地圖正中央 `(500, 500)` 的問道宗。宗門擴為 45 × 45 格（原為 19 × 19 格），配置主殿、雙側溪流與蓮池、六座玉橋、假山瀑布、涼亭及迎賓庭園。現有功能建築保留原座標與 ID，新增建築底座與外牆由瀏覽器／伺服器共用碰撞規則，四面城門可進出。溪流為真實水域，橋樑能步行通過，北側道路繞過主殿底座後連回北門。

周圍 73 × 73 格繼續保留安全區，宗門外維持平原，不生成妖獸、秘境、礦脈、海洋或隨機特殊地形。宗門園林不依種子變動，也不增加逐格資料庫讀寫；生成版本及既有進度格式相容。新翼園區隨十五格視野探索，不在首次登入額外揭露整片宗門。青竹林與古陣山口位於宗門東北側；外圍隨種子變化。實際畫面與驗證方式見 `design/world-sect/README.md`。

| 項目 | 預設種子 |
| --- | ---: |
| 地格 | 1,000,000 |
| 區塊 | 1,024（邊緣區塊裁切到實際範圍） |
| 陸地比例 | 約 70.2% |
| 生成秘境入口 | 450 |
| 生成結構 | 468 |
| 妖獸 | 2,730 |
| 連續礦脈 | 1,366 |

地形包括平原、竹林、樹林、荒漠、海洋、石域、火山，以及淺海／湖泊、海岸、山地、岩壁、雪原、濕地與不可步行的熔岩。高低、濕度、溫度與地質的連續種子雜訊形成大片生態，竹林與石域可步行穿越，熔岩必須繞行。

妖獸依生態選種，每個 32 × 32 區塊嘗試生成一群 3～6 隻的同種妖獸，遇到海岸、地貌邊界或障礙時縮減；相鄰區塊在相同的 96 × 96 棲地及生態中使用相同物種。竹林有靈狼／青竹蛇、樹林有山魈／妖藤、荒漠有沙蠍／蜥蜴、石域有巖甲獸／石靈、火山有赤焰獸／熔岩蜥蜴。怪物從中央宗門向外，每約 90 格提升一個境界帶，依序為煉氣、築基、金丹、元嬰、化神、煉虛、合體與大乘，生命與攻擊隨區域提升。材料沿用既有材料圖鑑，沒有產生圖鑑無法辨識的新 ID。

秘境目前提供陣紋探索與守衛戰棋兩種互動，不代表每個入口都已有獨立多層副本。結構包含望樓、祭壇、仙府遺跡和營地：望樓揭開迷霧、陣紋提供不需答題的探索獎勵、營地接入自由問道。個人採集與探索資格不會被其他玩家搶走；秘境機關進度與首次獎勵會存檔，重送請求不重複發獎。

海洋不能步行穿越。到水邊使用「乘舟」，沿水域逐格航行；駛到陸地／海岸才能上岸。航行模式會存檔，不會把點選遠處島嶼當成傳送。

## 種子、區塊與變更

每個世界的識別包含種子與生成器版本。首次建立世界時，伺服器將描述存入 `worldEvents/main`；環境變數 `WORLD_SEED` 可在首次建立前指定種子，未設定則使用預設種子。存檔建立後，如種子設定與既有世界不一致，API 會拒絕開啟。此版僅對同種子的 `qingyun-seeded-v1` 執行一次明確的 v2 遷移：交易內將原世界描述與區塊索引封存在 `worldEvents/archive:{舊 worldId}`，舊 `worldChunks` 文件保留，新的地貌使用新的世界 ID 與空變更索引；修橋／破陣的共享進度繼續生效。其他種子或未知版本不會自動遷移。

```json
{
  "seed": "qingyun-2026",
  "size": 1000,
  "chunkSize": 32,
  "generatorVersion": "qingyun-seeded-v2",
  "worldId": "qingyun-seeded-v2-ba95dee1"
}
```

基底地形和生成物件不逐格寫入資料庫。客戶端只生成視野／附近小地圖需要的區塊，生成快取最多 192 區塊；全世界分析放在模擬器的 Worker。實際遊戲尋路使用有節點及路程預算的 A*，戰鬥仍用 8 × 8 局部範圍。探索視野半徑為 15 格，前後端共用同一常數。迷霧只控制地形與物件的顯示，不限制尋路；點選迷霧內可通行的目的地也會前進。超出單次運算預算的長路線自動分段接續，抵達過程逐格揭開周圍視野，不預先揭露整條路線。海洋、岩壁與未解封機關仍依原有規則阻擋通行。

| 持久內容 | 文件 |
| --- | --- |
| 種子、版本、共享事件、修改區塊的版本索引 | `worldEvents/main` |
| 只保存有修改地格的區塊 | `worldChunks/{worldId}:{cx},{cy}` |
| 前一版世界描述與修改區塊索引 | `worldEvents/archive:{舊 worldId}` |
| 個人位置、航行模式、壓縮迷霧、任務、資格、機關與戰鬥 | `worldPlayers/{uid}` |

區塊變更使用局部索引 `localY × 32 + localX`，只記錄被修改的格子。修橋／破陣完成時，材料扣除、事件進度、地格變更及區塊版本在同一交易提交。一般瀏覽器不能任意提交地形變更。

客戶端比對附近區塊版本，只有變更版本不同時才請求 `patches`。伺服器透過版本索引跳過完全未修改的區塊，快取已讀取的變更；每次最多請求 25 個目前附近的區塊。移動路線經過有變更的區塊時，伺服器會載入其變更後重新驗證路線。缺失或版本不一致的變更文件不會被當成未修改地形放行。

迷霧是按區塊保存的十六進位位元圖，不再保存／傳送一百萬字元；初始迷霧小於 2 KB。位置仍在抵達、切換狀態與檢查點保存，未改為逐格 D1 寫入。版本不同的舊玩家第一次進入 v2 會回到中央問道宗，重新探索新地貌，清除舊版未完成的戰鬥、秘境與航行模式；修為、背包、採集／戰鬥計數、任務領取狀態及已領資格保留。生成物件 ID 也包含版本識別，舊座標的資格不會誤套到新棲地；v2 再次登入則恢復原本抵達的位置。

## 建置與驗證

```sh
npm ci
npm run build:world-simulator
npm run check:world-simulator
node --test tests/world-generation.test.cjs tests/world-core.test.cjs tests/world-api.test.cjs tests/world-battle.test.cjs
npm run build:module-versions
npm test
npm run audit:code
npm run check:module-versions
```

模擬器採確定性輸出，來源修改後重新建置單檔。靜態資源版本建置會先同步建置模擬器，檢查命令也會驗證單檔未過期。

本機畫面驗證：

```sh
WORLD_CHROMIUM_PATH=/path/to/chromium node scripts/capture-world-simulator.cjs
WORLD_CHROMIUM_PATH=/path/to/chromium node scripts/capture-grid-world.cjs
```

畫面擷取需要 Playwright；遊戲畫面沿用 `docs/grid-world.md` 的本機字型／Tailwind 擷取依賴。模擬器本身沒有這些執行依賴。驗證包含瀏覽器與 Node 地形指紋一致、不同種子與載入順序、區塊接縫／邊界、快取上限、連續礦脈、修改區塊讀取量、壓縮迷霧、遠距尋路、秘境存檔與領獎、航行恢復，以及單檔離線操作、JSON 往返和 PNG 匯出。

結果與圖例：`docs/design/seed-world/`；真實 API 與原介面下的生成區域畫面：`docs/design/grid-world/generated-*.png`。測試使用隔離樣本，不登入正式帳號或寫入正式資料。即時同步仍沿用現有單一 Render 程序 SSE；此變更沒有宣稱完成多節點或千人負載測試。
