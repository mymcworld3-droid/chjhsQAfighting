# 體力戰棋與問道獵妖

分支：`stamina-battle`。單人試煉採伺服器權威的種子關卡與任務結算。

## 入口與操作

畫面沿用整站的固定舞台：橫式以 1280×720（16:9）、直式以 360×640（9:16）排版，再由同一個 `game-frame` 等比縮放並置中，剩餘空間保持黑色。戰場、雲幕、題目與結算彈窗皆受同一舞台限制，戰場尺寸不改變畫面比例。

戰場內容使用獨立的區域容器，避免誤套全站 `main` 預留給導覽列的上下間距。直式將回合資訊與收起按鈕排在標題同列，壓縮狀態／操作區的間距，地圖使用剩餘高度；不再以固定最小高度把下方操作擠出舞台。移動、攻擊、技能、護身與結束回合皆完整留在畫面內。

視覺沿用原問道試煉的墨金配色、山水底圖、金邊題目卡、選項與正誤色彩。題目及作答回顧共用原站主題的 CSS 宣告，僅增加對戰棋元件的選擇器；不在頁面重複使用原問道的元素 ID，也不接管舊答題控制器。走位、答題補充體力及逐關打怪的流程維持現行戰棋規則。

LaTeX 公式跟隨所在欄位的文字顏色，涵蓋題幹、選項、解析及白板的 MathJax CHTML／SVG 子元素。

- 首頁「問道試煉」按下後立即啟動既有全螢幕雲幕，在雲幕遮住畫面時載入目前關卡，直接進場；不顯示地形或分支選擇。既有任務入口也走相同流程。「鬥法論道」維持雙人配對入口。
- 兩個入口各自恢復同模式的戰場，未結束的試煉不會攔截鬥法配對或房間代碼加入；收起鬥法後仍可繼續原試煉。伺服器以 `roomIds.pve`／`roomIds.pvp` 分別保存續戰房間，讀取、同步與衝突重試均指定模式。舊版僅有 `roomId` 的紀錄會在首次切換模式時保留原房間，無須重置進度；試煉通關與妖獸介紹亦核對試煉自己的房間。
- 問道試煉逐關推進；新版包含討伐、鎮守、封印與首領。靈獸依關卡與地形配置，首次遇見的種類維持既有介紹。
- 單人關卡依模式選用 7×7 至 13×9 地圖，地形、障礙、陣眼與敵人由種子決定；放置障礙時檢查連通性，首領地圖另檢查 2×2 占位的移動空間。雙人鬥法仍可選演武庭、青竹幽徑或古陣遺墟。
- 選「移動」時，以灰色閃動標出現有體力能走到的空格；依實際繞路與緩速計算，排除障礙及有人佔據的地格。點選後預覽路線與實際消耗。方向鍵也可選地格。
- 選「攻擊」時，以紅格顯示上下左右各兩格，點任一紅格選擇該方向，再確認攻擊；該方向兩格的敵人都會受傷，一次只扣 2 體力、佔用一次攻擊次數，遇障礙及地圖邊緣停止。選擇空的方向也會消耗體力。
- 選「金丹技能」時，依各分支現有射程與形狀顯示紅格；直線、範圍、位移與自身技能各自保留原規則，選定後加深命中區。踏陣破障會預覽落點相鄰的爆發範圍。紅格代表射程，體力／冷卻等施放限制由確認按鈕與伺服器驗證。敵方預告另用紅色虛線框，隕星維持紫格。
- 點「結束回合」才輪到敵人；答題本身不會自動攻擊。護身不耗體力，佔用一次攻擊／技能次數，減傷 40%。
- 通關彈窗直接提供「前往下一關」，失敗提供「重試本關」，兩者都沿用雲幕進場；不返回選地圖大廳。每關重新補滿生命並恢復初始體力。「收起」保留進度；「離開戰場」需確認認輸。重新整理後可回到同一關與未答題目；重試不重抽地形與敵人。

## 行動動畫

玩家、妖獸與雙人鬥法對手的行動，依伺服器已提交的事件順序播放。畫面保留墨金風格、既有圖集與固定比例；動畫、文字與粒子都畫在原戰場範圍內。按鈕有按壓回饋，進場原位淡入，題目、介紹與結算彈窗淡入；戰況文字過長時省略顯示，避免動畫途中推擠地圖。橫式戰況紀錄可縮小並捲動，保留底部操作空間。

| 行動 | 畫面效果 |
| --- | --- |
| 移動 | 沿實際路線逐格行走；妖獸分別呈現重步、蛇行、橫移、疾進、跳躍、飛行及瞬移 |
| 普攻與劍技 | 朝選定方向出招，兩格／多格斬痕與命中回饋；劍遁先突進再斬擊 |
| 金丹神通 | 按分支色彩與形狀呈現潮波、雷光、神念、回復、護盾、換位等效果；隕星標記與實際落下分開播放 |
| 妖獸攻擊 | 按已鎖定的紅框顯示爪擊、直線射擊、衝撞、扇形吐息、震波、毒環與靈爆；山魈／霜羽鷹先躍入再攻擊 |
| 命中／擊退 | 角色短暫受擊亮色、退縮、生命條遞減與傷害／吸收數字；擊退沿實際可行路徑播放 |
| 回復／補充體力 | 回復數字與上升靈光；作答回顧關閉後才播放體力獲得效果 |
| 護身／等待／閃避 | 護身符印、蓄勢光環、閃避動作與提示 |
| 換回合／離場／勝負 | 交接提示、收法淡出；擊倒淡出後才顯示勝負光效與結算彈窗 |

新事件帶有精簡的演出資料（路徑、命中格及數值變化），沿用原事務保存，沒有新增動畫 API 或額外資料庫寫入。事件使用房內遞增序號，保留最近 28 筆時仍可辨識每次出招。初次載入、相同 revision、已看過的事件與舊回應不重播；重新進場直接顯示最新戰況。舊版移動事件仍可播放。

`tactical-animation.js` 只建立與取樣視覺時間軸，不改動伺服器結果。範圍傷害同時播放，反擊保留獨立順序；單批連續行動最多 4.2 秒。播放期間暫停新的戰鬥操作，收起及離場仍可使用；角色擊倒與最後一段動畫完成後再開啟結算。彈窗和背景分頁會凍結當前進度，返回後接續；關閉戰場會取消畫布排程。雙人回合時鐘仍按伺服器時間運作。減少動態效果偏好會直接顯示最終結果，並關閉位移、粒子與介面轉場。

## 體力與勝負

| 項目 | 規則 |
| --- | --- |
| 初始／上限體力 | 2／10；未用完可留到下回合 |
| 答題 | 答對 +4，答錯 +1；每次自身回合最多兩題 |
| 移動 | 四向尋路，每格 1；緩速時單次最多移動 2 格 |
| 普攻 | 四向擇一，沿該方向攻擊兩格，消耗 2 |
| 功法技能 | 裝備後取代普攻；所有功法技能無冷卻，仍受體力、出手次數及射程限制；金丹技能停用 |
| 行動上限 | 每次自身回合兩次攻擊／技能，總操作最多 16 次 |
| 雙人鬥法 | 築基解鎖；按選定地圖配對，也可分享 16 碼戰場代碼 |
| 雙人答題 | 每輪雙方同時各答兩題，先完成者先行動；另一方從此刻起倒數 50 秒，未完成的題目不增加體力 |
| 雙人行動時間 | 每人 30 秒；連續兩次自身行動逾時判負；先手行動與後手答題倒數各自運作 |
| 勝利條件 | 擊倒所有敵方；總回合超過 60 時，PvP 比生命比例，PvE 判挑戰失敗 |

問道試煉四分之一圓戰鬥介面新增攻擊不可用提示：體力不足、出手或總行動次數用盡、非自身回合、動畫或伺服器操作進行中，以及選錯地格／距離／視線／技能落點時，於兩側操作輪上方顯示具體原因。已停用的確認按鈕仍隱藏，合法地格點擊即出招。舊戰鬥資料的冷卻時間戳記不再阻止技能使用。

### 錯題體力返還

問道試煉的「問題回報」與問道助手自動回報，均須通過獨立審核。確認錯題後，已答錯的題目補回相較答對少取得的體力，通常為 3 點；以原作答時的體力上限計算，實際返還後仍不得超過 10。已答對的題目不重複給體力。

尚未作答就確認有誤時，略過該題並取得答對應得的體力（最多 4 點），使用本回合一次答題機會，不新增答題紀錄或答對次數。前端立即同步戰場體力與提示，沿用體力恢復動畫。修為補償的每日上限不影響體力修正。試煉回報補償修為及體力。

返還紀錄與戰場更新在同一筆交易完成；重複回報、並行請求與遺失回應重試只會返還一次。審核失敗、未確認有誤、非本場參戰者與已結束戰場不會增加體力，舊戰場的延遲回報也不影響新關卡。

雙方題目依各自帳號已儲存的學制、範圍及難度簽發；答案與作答速度不決定先攻。每場角色數值、金丹及分支會固定，戰鬥中更換裝備不會重算。

未結丹玩家可使用調息護元。分支選擇維持在既有元神頁面，原本的兩條神通變化與升階方式不變，卡片和詳情會顯示對應戰場技能。元神選擇透過 `SPIRIT_BRANCHES` 對應戰場招式，進場自動採用已保存的變化；客戶端進場請求不能覆寫分支。舊版尚未覺醒元神的帳號沿用原已存 `tacticalPreferences` 或預設分支。

攻擊與生命沿用現有伺服器可信快照，包含境界、元嬰及裝備的攻擊／生命投影和開場護盾；對低境界對手繼續封印元嬰攻擊／生命加成。戰棋的金丹效果由上述主動技能提供，舊自動連擊、機率金丹技能及本命神通結算鏈沒有額外疊入戰棋；原團本及修煉規則保持各自的現行結算。

## 妖獸與首次遭遇

首次出現的新種類會在雲幕開啟後介紹，沿用墨金彈窗與既有妖獸圖片，以攻擊方式為主，另列移動方式與應對。一次遇到多種時依序介紹。按「記住招式」才保存；直接收起或重整會保留未讀介紹，讀過的種類不因重試或換裝置重複彈出。

介紹內建循環的「招式演練」小戰場：先展示該種類的實際移動，再依序演示紅框預告、站在危險格被命中、修士移出紅框，以及原招式落空。古陣守衛分別演練落石與十字；毒環、震波、扇形與靈爆保留完整形狀。演練直接用共用戰鬥規則計算移動、傷害、擊退與落點，搭配正式戰鬥的角色圖集及動畫渲染，不以裝飾動畫代替規則。鏡頭依整段演練的角色、路徑、障礙及所有紅框取景，保留一格餘裕；手機上的近身招式可放大顯示，完整攻擊形狀與格子間距不變。

演練提供暫停／播放與重播；背景分頁會暫停，關閉介紹、切換下一種或離開戰場會釋放動畫。減少動態效果時改為「下一步」靜態演練。顯示方式維持原墨金風格與固定舞台比例，確認／收起按鈕留在彈窗底部，較長的說明在中間區域捲動。模擬使用獨立的示範角色與快照，不呼叫 API、不寫入已讀紀錄，也不消耗真實體力或更動關卡、生命與獎勵。

## 保存與獎勵

- 所有戰場 API 驗證既有主帳號登入票證；客戶端只送選項或地格，不能指定答題正誤、扣血、角色金丹、體力或獎勵。
- `tacticalBattleRooms` 與 `tacticalBattlePlayers` 只由伺服器存取。關卡種子、目前關數與最高通關數的權威進度放在後者的 `trial`；玩家文件的 `tacticalTrialV1` 只是顯示鏡像，不能用來指定或跳過關卡。沿用現有玩家 repository（含 D1 adapter），讓體力、答題紀錄與獎勵和玩家資料在同一事務寫入。不需要新增環境變數、資料搬遷或瀏覽器資料庫權限。
- 每個行動使用 request ID 及狀態 revision；答案綁定房間、參戰玩家、回合、題號。重送已提交的請求不重複扣體力、答題計數或發獎。
- 答題前的快照刪除正解與解析；生成中的延遲回應若已跨回合會被拒絕。出題繼續通過 `/api/generate-quiz` 的學制、格式、品質、知識點及重複題驗證。
- 試煉答題加體力及修為，靈石於通關結算；修為沿用元嬰分支及學習加成，金丹期後答錯扣一修為。更新固定知識點、舊知識圖譜、連答數、問道任務與 `exam_logs`。

## 同步答題與題目協助（2026-10-25）

雙人新場採同步答題輪：雙方各自載入兩題，即使體力已滿仍須完成兩題。第二題答案先由伺服器提交者取得該輪先手，立刻開始 30 秒行動；對方可繼續作答，50 秒答題倒數從先手完成第二題時開始，與行動倒數獨立。先手先結束但對方未答完時等待；對方答完或 50 秒到期後開始其 30 秒行動。逾時未答題不計入答題紀錄，也不提供體力，保留已答題獲得的體力。兩人行動完畢才重開下一輪，先手重新競爭，體力繼續保留。伺服器在重新同步時按時間順序處理逾時，重連不延長既有倒數；答題及行動皆可安全重送。

對方提交答案不會令已選定的合法行動失效：行動另帶 `actionRevision`，真實行動或回合切換仍會使舊行動失效。題目生成以 `quizRound` 驗證，對方先行動或結束行動不會廢棄尚在生成的本輪題目。配對前已存在且沒有 `quizRound` 的進行中舊場保留舊輪替流程，重新開場才使用新流程。

體力獲得事件於答題／解析彈窗內暫停，按返回戰場後播放；同步狀態不關閉彈窗、不消耗暫停中的動畫。兩題間按「繼續第二題」保持暫停。

## 第四階段：效能、輸入與響應式驗收（2026-11-18）

- 場景快取改用 `Ambience.mapIdentity()`：包含關卡種子／布局、地形、地面圖集值與障礙物座標及類型，不再僅以 room ID 或障礙數量判斷。相同房間進入下一關、即使地圖大小與障礙物數量一樣，也會重新生成正確的靜態圖層。角色生命、移動、回合變動不會觸發此快取重建。
- `Ambience.stageIdentity()` 獨立判斷戰場關卡的轉換：切換關卡時清空已排隊但屬於上一關的演出、清除手勢與選中目標，鏡頭回到新關卡初始視野；同關回合更新則保留玩家拖曳的鏡頭、不中斷既有技能演出。
- `Ambience.pixelRatioFor()` 將畫布 backing store 限制在記憶體預算（低記憶體裝置約 220 萬 pixels；一般裝置約 330 萬 pixels）。可視 CSS 尺寸、地格 hit test、16:9／9:16 固定舞台不變；適合的手機仍盡可能保留高解析度。
- 指標控制在觸控 `pointerup` 才收到超過 8px 位移、或遇到 `pointercancel`／`lostpointercapture` 時，一樣視為拖曳／取消操作，阻止後續合成 click 誤選地格。雙指縮放仍保持原本相機與地格映射。
- 靈獸資訊卡和清單現在只在內容變更時替換 DOM，保留捲動位置與原本聚焦按鈕；對話框加入 `aria-modal`、Tab／Shift+Tab 焦點限制、Escape 返回開啟來源，展示資訊時背景戰場設為 inert。進入題目與演練的彈窗依舊保留背景 inert，不讓資訊卡的清理將其意外解除。
- 離開戰場時清除場景快取與背景計時器，解除圖集圖片 onload/onerror 的監聽；已存在的低頻環境動畫及 reduced-motion 行為保持。
- 高頻 `pointermove`、滾輪縮放與 `ResizeObserver` 現在以 `requestAnimationFrame` 合併重繪；一個顯示影格內即使收到多次拖曳事件，也只重畫一次，保留每次手勢累積的實際鏡頭位置。關閉時連預約中的手勢影格一併取消。

驗證：`tests/tactical-ambience.test.cjs` 新增同尺寸不同關卡、同數量障礙、改動水面地格、回合／生命改動不刷新與 DPR 記憶體預算。`scripts/test-tactical-browser.cjs` 新增手機尺寸的拖曳／雙指捏合誤觸、同房間換場景、靈獸資訊卡鍵盤焦點、題目／招式示範背景隔離與畫布像素上限驗證。

## 第五階段：危險格與戰術辨識（2026-11-18）

- 新增純展示模組 `public/cultivation/tactical-threat-visuals.js`。只讀取 PvE 已確認的 `actor.intent.cells` 與當前關卡 `objective.hazards`，依來源去重、限制在實際地圖內；不重新預測 AI 行為、不改動回合、傷害、體力或戰鬥結算。PvP 保留原本顯示。
- 只呈現有效攻擊預告（`attack`、`boss-attack`、`defense-attack`、`strike`）。`advance`、`wait` 與已擊敗靈獸不會被渲染成攻擊；若敵人被推開或移位，已鎖定預告的 `origin` 與實際位置不同，就不繼續顯示失效的舊攻擊格。
- 危險範圍以淡色底紋、斜線提示和**連續外邊框**表現，避免與玩家主動技能的紅色射程混淆，也照顧色覺差異。重疊攻擊以同一格呈現，不重覆加深遮蔽角色；首領預告使用較鮮明的外框。描邊在角色圖層之後，仍能在竹林、障礙物或大型靈獸旁看清預告邊界。
- 若玩家當前位置被已確認預告涵蓋，玩家地格顯示固定的驚嘆號警示。只有在玩家**輪到自己移動且真的可達**時，才挑選最多兩個「不在目前預告內」的移動落點，用小型青綠勾號作為躲避參考。這些標記**不宣稱保證安全**：敵人接下來的移動、未知攻擊或其他機關仍可能有危險。
- Canvas 提供對應的 `aria-description`；以不可見、非互動的 `role=status` 即時回報危險格與目前地格是否被標記。保留原有頂部資訊列、左右四分之一圓、移動／攻擊、答題充能和地圖拖曳縮放。沒有增加按鈕或阻擋戰場點擊。
- 計算投影放在狀態更新時，動畫影格只畫快照，避免重覆搜尋移動格；關卡、敵人意圖與技能模式變動時更新。`prefers-reduced-motion` 不影響警示清晰度，也不需要任何閃爍。

測試：`tests/tactical-threat-visuals.test.cjs` 檢查伺服器意圖去重、過期攻擊預告、首領與場地危險、出界與死亡敵人、真實可達的躲避落點、PvP 隔離和 Canvas 純視覺性；`scripts/test-tactical-browser.cjs` 加入手機畫面、提示文字、隱藏無障礙說明與來源失效後的提示消失驗收。

## 第六階段：無需額外確認的路線與技能預覽（2026-11-18）

- 新增純視覺 `public/cultivation/tactical-target-visuals.js`：依既有 `tactical-rules.js` 同源的 BFS `path()`、`moveCells()`、`validateSkill()`、`techniquePreview()` 推導地圖上的路線逐格序號、總體力消耗、施放目標與可能被範圍涵蓋的靈獸。絕不自行估計實際傷害、抗性、擊殺數或判定操作成功。
- 地圖上選取移動格時，畫出正確繞路路線、逐格數字與終點體力需求。體力不足、無法通行或緩速移動上限外不會顯示為可執行的目的地。移動落點若屬上一階段真實攻擊預告危險格，僅標示已知危險，不承諾其他位置必然安全。
- 施放一般攻擊或功法時，用輪廓標出本次技能預覽範圍內的敵人，並附精簡的『N 名敵人』標籤；身為同一個大型首領的多格占位只計為一名，沒有未經規則確認的傷害數字。
- **維持單次點擊立即執行原有操作**，沒有增加第二次確認。桌面滑鼠懸停在地格就能事先看到對應路線或技能覆蓋範圍；手機在非靈獸地格停按約 500ms 可以只預覽而不觸發移動或攻擊。原本長按靈獸查看資料的功能維持不變；拖曳、雙指縮放和取消手勢不會送出攻擊。
- 計算預覽只在選取或滑鼠跨入新地格時進行，Canvas 重繪不重跑 BFS。新覆蓋圖層只在單人問道試煉有作用；鬥法維持原本的場地與輸入流程。
- 測試：`tests/tactical-target-visuals.test.cjs` 覆蓋真實路徑、體力不足、緩速、回合權限、技能射程、影響目標去重及資料不可變性。`scripts/test-tactical-browser.cjs` 加入手機直橫式、懸停預覽、長按後 click 被阻擋與伺服器版本／體力不變驗證。
