# 體力戰棋與問道獵妖

分支：`stamina-battle`。基於 `main` 的 `aacf45f9`；只借用 `grid-world` 的點陣素材，未合併大世界功能。

## 入口與操作

畫面沿用整站的固定舞台：橫式以 1280×720（16:9）、直式以 360×640（9:16）排版，再由同一個 `game-frame` 等比縮放並置中，剩餘空間保持黑色。戰場、雲幕、題目與結算彈窗皆受同一舞台限制，戰場尺寸不改變畫面比例。

戰場內容使用獨立的區域容器，避免誤套全站 `main` 預留給導覽列的上下間距。直式將回合資訊與收起按鈕排在標題同列，壓縮狀態／操作區的間距，地圖使用剩餘高度；不再以固定最小高度把下方操作擠出舞台。移動、攻擊、技能、護身與結束回合皆完整留在畫面內。

視覺沿用原問道試煉的墨金配色、山水底圖、金邊題目卡、選項與正誤色彩。題目及作答回顧共用原站主題的 CSS 宣告，僅增加對戰棋元件的選擇器；不在頁面重複使用原問道的元素 ID，也不接管舊答題控制器。走位、答題補充體力及逐關打怪的流程維持現行戰棋規則。

LaTeX 公式固定白色，涵蓋題幹、選項與解析的 MathJax CHTML／SVG 子元素，避免沿用舊宣紙題卡的深墨色。

- 首頁「問道試煉」按下後立即啟動既有全螢幕雲幕，在雲幕遮住畫面時載入目前關卡，直接進場；不顯示地形或分支選擇。既有任務入口也走相同流程。「鬥法論道」維持雙人配對入口。
- 問道試煉逐關推進，每關依種子決定 1～4 隻怪物；第 1～20 關各介紹一種新怪物，之後依地形混合已解鎖種類。第 10 關起，每五關可遇鎮關守衛。生命／攻擊隨關數成長，各種類保留自己的移動與攻擊方式。
- 單人關卡隨機選取 7×7、9×7、11×9 戰場大小，搭配竹林、荒漠、雪嶺、庭苑或遺墟地形；石障、樹木、水域與出生點由種子生成。每次放置障礙後檢查地面連通性，確保敵我不被封死。雙人鬥法仍可選演武庭、青竹幽徑或古陣遺墟。
- 選「移動」時，以灰色閃動標出現有體力能走到的空格；依實際繞路與緩速計算，排除障礙及有人佔據的地格。點選後預覽路線與實際消耗。方向鍵也可選地格。
- 選「攻擊」時，以紅格顯示上下左右各兩格，點任一紅格選擇該方向，再確認攻擊；該方向兩格的敵人都會受傷，一次只扣 2 體力、佔用一次攻擊次數，遇障礙及地圖邊緣停止。選擇空的方向也會消耗體力。
- 選「金丹技能」時，依各分支現有射程與形狀顯示紅格；直線、範圍、位移與自身技能各自保留原規則，選定後加深命中區。踏陣破障會預覽落點相鄰的爆發範圍。紅格代表射程，體力／冷卻等施放限制由確認按鈕與伺服器驗證。敵方預告另用紅色虛線框，隕星維持紫格。
- 點「結束回合」才輪到敵人；答題本身不會自動攻擊。護身不耗體力，佔用一次攻擊／技能次數，減傷 40%。
- 通關彈窗直接提供「前往下一關」，失敗提供「重試本關」，兩者都沿用雲幕進場；不返回選地圖大廳。每關重新補滿生命並恢復初始體力。「收起」保留進度；「離開戰場」需確認認輸。重新整理後可回到同一關與未答題目；重試不重抽地形與敵人。

## 行動動畫

玩家、妖獸與雙人鬥法對手的行動，依伺服器已提交的事件順序播放。畫面保留墨金風格、既有圖集與固定比例；動畫、文字與粒子都畫在原戰場範圍內。按鈕有按壓回饋，進場原位淡入，題目、介紹與結算彈窗淡入；戰況文字過長時省略顯示，避免動畫途中推擠地圖。橫式戰況紀錄可縮小並捲動，保留底部操作空間。

| 行動 | 畫面效果 |
| --- | --- |
| 移動 | 沿實際路線逐格行走；妖獸分別呈現重步、蛇行、橫移、疾進、跳躍、飛行及瞬移 |
| 普攻與劍技 | 朝選定方向出招，兩格／多格斬痕與命中回饋；劍遁先突進再斬擊 |
| 金丹神通 | 按分支色彩與形狀呈現潮波、雷光、神念、回復、護盾、換位等效果；隕星標記與實際落下分開播放 |
| 妖獸攻擊 | 按已鎖定的紅框顯示爪擊、直線射擊、衝撞、扇形吐息、震波、毒環與靈爆；山魈／霜羽鷹先躍入再攻擊 |
| 命中／擊退 | 角色短暫受擊亮色、退縮、生命條遞減與傷害／吸收數字；擊退沿實際可行路徑播放 |
| 回復／補充體力 | 回復數字與上升靈光；作答回顧關閉後才播放體力獲得效果 |
| 護身／等待／閃避 | 護身符印、蓄勢光環、閃避動作與提示 |
| 換回合／離場／勝負 | 交接提示、收法淡出；擊倒淡出後才顯示勝負光效與結算彈窗 |

新事件帶有精簡的演出資料（路徑、命中格及數值變化），沿用原事務保存，沒有新增動畫 API 或額外資料庫寫入。事件使用房內遞增序號，保留最近 28 筆時仍可辨識每次出招。初次載入、相同 revision、已看過的事件與舊回應不重播；重新進場直接顯示最新戰況。舊版移動事件仍可播放。

`tactical-animation.js` 只建立與取樣視覺時間軸，不改動伺服器結果。範圍傷害同時播放，反擊保留獨立順序；單批連續行動最多 4.2 秒。播放期間暫停新的戰鬥操作，收起及離場仍可使用；角色擊倒與最後一段動畫完成後再開啟結算。彈窗和背景分頁會凍結當前進度，返回後接續；關閉戰場會取消畫布排程。雙人回合時鐘仍按伺服器時間運作。減少動態效果偏好會直接顯示最終結果，並關閉位移、粒子與介面轉場。

## 體力與勝負

| 項目 | 規則 |
| --- | --- |
| 初始／上限體力 | 2／10；未用完可留到下回合 |
| 答題 | 答對 +4，答錯 +1；每次自身回合最多兩題 |
| 移動 | 四向尋路，每格 1；緩速時下次移動每格 2 |
| 普攻 | 四向擇一，沿該方向攻擊兩格，消耗 2 |
| 金丹技能 | 消耗 3～4；施放後第二次自身回合才可再用 |
| 行動上限 | 每次自身回合兩次攻擊／技能，總操作最多 16 次 |
| 雙人鬥法 | 築基解鎖；按選定地圖配對，也可分享 16 碼戰場代碼 |
| 雙人答題 | 每輪雙方同時各答兩題，先完成者先行動；另一方從此刻起倒數 50 秒，未完成的題目不增加體力 |
| 雙人行動時間 | 每人 30 秒；連續兩次自身行動逾時判負；先手行動與後手答題倒數各自運作 |
| 勝利條件 | 擊倒所有敵方；總回合超過 60 時，PvP 比生命比例，PvE 判挑戰失敗 |

雙方題目依各自帳號已儲存的學制、範圍及難度簽發；答案與作答速度不決定先攻。每場角色數值、金丹及分支會固定，戰鬥中更換裝備不會重算。

## 妖獸與首次遭遇

首次出現的新種類會在雲幕開啟後介紹，沿用墨金彈窗與既有妖獸圖片，以攻擊方式為主，另列移動方式與應對。一次遇到多種時依序介紹。按「記住招式」才保存；直接收起或重整會保留未讀介紹，讀過的種類不因重試或換裝置重複彈出。

介紹內建循環的「招式演練」小戰場：先展示該種類的實際移動，再依序演示紅框預告、站在危險格被命中、修士移出紅框，以及原招式落空。古陣守衛分別演練落石與十字；毒環、震波、扇形與靈爆保留完整形狀。演練直接用共用戰鬥規則計算移動、傷害、擊退與落點，搭配正式戰鬥的角色圖集及動畫渲染，不以裝飾動畫代替規則。鏡頭依整段演練的角色、路徑、障礙及所有紅框取景，保留一格餘裕；手機上的近身招式可放大顯示，完整攻擊形狀與格子間距不變。

演練提供暫停／播放與重播；背景分頁會暫停，關閉介紹、切換下一種或離開戰場會釋放動畫。減少動態效果時改為「下一步」靜態演練。顯示方式維持原墨金風格與固定舞台比例，確認／收起按鈕留在彈窗底部，較長的說明在中間區域捲動。模擬使用獨立的示範角色與快照，不呼叫 API、不寫入已讀紀錄，也不消耗真實體力或更動關卡、生命與獎勵。

## 保存與獎勵

- 所有戰場 API 驗證既有主帳號登入票證；客戶端只送選項或地格，不能指定答題正誤、扣血、角色金丹、體力或獎勵。
- `tacticalBattleRooms` 與 `tacticalBattlePlayers` 只由伺服器存取。關卡種子、目前關數與最高通關數的權威進度放在後者的 `trial`；玩家文件的 `tacticalTrialV1` 只是顯示鏡像，不能用來指定或跳過關卡。沿用現有玩家 repository（含 D1 adapter），讓體力、答題紀錄與獎勵和玩家資料在同一事務寫入。不需要新增環境變數、資料搬遷或瀏覽器資料庫權限。
- 每個行動使用 request ID 及狀態 revision；答案綁定房間、參戰玩家、回合、題號。重送已提交的請求不重複扣體力、答題計數或發獎。
- 答題前的快照刪除正解與解析；生成中的延遲回應若已跨回合會被拒絕。出題繼續通過 `/api/generate-quiz` 的學制、格式、品質、知識點及重複題驗證。
- 問道答對沿用境界靈石公式及元嬰修為分支；金丹期後答錯扣一修為。更新固定知識點、舊知識圖譜、連答數、問道任務與 `exam_logs`。
- PvE 第 n 關通關額外獲得 `35 + min(100, (n-1)×5)` 靈石及 2＋元嬰分支修為；至少答對一題才可領取額外獎勵。清除敵人後，下一關與最高通關數同一事務更新；重送通關不重複前進。PvP 勝利 500 靈石及 5＋元嬰分支修為，落敗 200，平手 250 及 2 修為；雙方合計至少完成兩題才算正式結算及鬥法任務。
- 通關獎勵、雙方任務計數與房間結束標記同一事務提交。重整、斷線重送及同時結算均不重複發獎。伺服器回傳自己帳號的最新進度，畫面立即更新。
- 等待配對或雙人戰場啟用時輪詢；即使正在答題也保留題目彈窗並更新對手狀態與倒數，背景分頁暫停；單人場不輪詢。連線失敗採退避；停用舊問道題目預載及舊鬥法監聽，避免雙套流程同時耗用。
- 妖獸已讀種類存在私有 `tacticalBattlePlayers.bestiary.seen`，已讀清單最多 20 個種類 ID。`/api/tactical/acknowledge-enemy` 驗證登入、目前房間與實際遭遇種類，同一事務更新已讀與房內待介紹佇列；重送不重複保存，也不改變戰鬥 revision、體力或獎勵。一般讀取不為介紹額外寫入資料庫。

答題與作答回顧在直式、橫式都與載入相同正式樣式的原問道頁面比對：題卡底色／邊框、題幹字級／行高、選項顏色／圓角，包含答對及未選選項。題目開啟時使用原山水底圖覆蓋戰場，避免地圖與操作文字透到題卡後面。

動畫測試涵蓋未結丹與九丹十八分支、20 種怪物的實際命中範圍／移動風格、同時傷害、擊退／雙人換位／吸血／反擊、延遲隕石、死亡淡出、有限時間軸、舊紀錄與重送不重播。瀏覽器實際操作移動、攻擊、技能、怪物換手、護身、答題、通關與減少動態；檢查動畫期間禁止重複操作、離場彈窗凍結／接續、重新同步不重播、擊倒先於結算，並將所有金丹及怪物效果在不同進度繪入真正畫布，比對像素確實變化。

## 同步答題與題目協助（2026-10-25）

雙人新場採同步答題輪：雙方各自載入兩題，即使體力已滿仍須完成兩題。第二題答案先由伺服器提交者取得該輪先手，立刻開始 30 秒行動；對方可繼續作答，50 秒答題倒數從先手完成第二題時開始，與行動倒數獨立。先手先結束但對方未答完時等待；對方答完或 50 秒到期後開始其 30 秒行動。逾時未答題不計入答題紀錄，也不提供體力，保留已答題獲得的體力。兩人行動完畢才重開下一輪，先手重新競爭，體力繼續保留。伺服器在重新同步時按時間順序處理逾時，重連不延長既有倒數；答題及行動皆可安全重送。

對方提交答案不會令已選定的合法行動失效：行動另帶 `actionRevision`，真實行動或回合切換仍會使舊行動失效。題目生成以 `quizRound` 驗證，對方先行動或結束行動不會廢棄尚在生成的本輪題目。配對前已存在且沒有 `quizRound` 的進行中舊場保留舊輪替流程，重新開場才使用新流程。

體力獲得事件於答題／解析彈窗內暫停，按返回戰場後播放；同步狀態不關閉彈窗、不消耗暫停中的動畫。兩題間按「繼續第二題」保持暫停。

問道試煉在選項及解析下方提供「錯題回報」與「問道助手」，預設收合以保留題目空間。助手沿用 `/api/question-helper`，可討論觀念、核對作答及解析；確認疑似錯題時自動交由獨立審核。回報使用已登入的 `/api/tactical/report-question`，從伺服器的待答題或最近一題回顧取得題幹、選項、正解與解析，忽略客戶端偽造答案。沿用既有兩次 AI 審核、每日限額及單題補償去重；作答前隱藏可能洩題的審核理由。協助請求綁定帳號、房間與題目，切題或離場取消請求並忽略舊回應，不接管舊問道頁的全域題目或跳題函式。
