# 修行任務

宗門首頁的「仙道」獨立顯示主線任務，並保留境界圖錄入口；「任務」顯示日常、宗門委託與每週任務。兩個入口各自顯示可領獎紅點。玩家可查看進度、獎勵、前往對應玩法，達標後手動領取。

## 仙道（新版）

共 28 項，依序開啟。保留既有劇情、出題範圍、問道答題、每日閉關、正式鬥法及境界里程碑；移除三項已停用舊團本任務、重複五場鬥法任務及尋訪洞天。洞天為選用功能，不列入仙道、日常、宗門委託或每週任務。第二章竹簡天尊僅為劇情觀看，不需使用洞天。劇情完成紀錄與既有有效領獎 ID 繼續使用。

新增四項：問道試煉第 1、5、10 關與首次通關武器副本。通關以伺服器 `tacticalBattlePlayers/{uid}.trial.best` 及 `weaponDungeonV1.clears` 為準，既有通關直接計入，開啟副本或答題不算通關。

### 境界突破與副本

金丹、元嬰、化神、煉虛、合體、渡劫、半仙分別要求累計成功通關武器副本 1、3、6、10、15、21、28 次。任何難度成功通關皆計次；失敗、進場或消耗副本券不計。仙道在對應境界任務前顯示通關目標。修為達門檻但通關不足時，實際修為停在門檻前 1 點，額外修為暫存；成功通關達標時自動釋放暫存修為，仍須滿足下一境界條件。已達境界不追溯降級。真仙原有仙位規則不變。

只有下列五個里程碑給副本券，其餘任務給靈石或修為，不給券：

| 任務 | 副本券 |
| --- | --- |
| 築基立道 | 1 |
| 丹成大道 | 1 |
| 初探秘境 | 2 |
| 元嬰出竅 | 2 |
| 百問悟道 | 2 |

全線合計 8 張。副本券與領獎交易同時存入伺服器錢包；每日補發上限 5 張，任務取得的超額券保留。已發放的舊抽獎券、副本券、靈石、材料及修為不收回；只補發新版仍有副本券獎勵且未領足的差額。已停用任務及其領獎 ID 保留在歷史紀錄，不出現在新版進度分母，也不阻擋下一任務。

## 日常

| 任務 | 條件 | 獎勵 |
| --- | --- | --- |
| 溫故知新 | 今日問道答對 3 題 | 40 靈石、1 修為 |
| 勤學不輟 | 今日問道答對 10 題 | 80 靈石、1 修為 |
| 靜心閉關 | 今日完成閉關，無須全對 | 30 靈石 |
| 論道切磋 | 今日完成正式鬥法 1 場，勝負皆計 | 80 靈石 |
| 同門協力 | 今日成功通關團本 1 次 | 100 靈石、1 修為、淬靈玄印 1 枚 |

日常進度與領獎資格依 `Asia/Taipei` 每日 00:00 重置；仙道進度不重置。當日未領獎勵不保留至次日。兩個問道任務分別領取，答對 10 題時可領兩項。鬥法及團本入口與領獎需達築基初期（10 修為）。練習鬥法與洞天教學範例不計正式活動；退出、配對或僅開啟玩法不計次。

每週「百藝兼修」只累積閉關或正式鬥法；洞天結算不再計入任務。當日已派發洞天委託時替換該欄位，保留其他委託與已領紀錄。

## 資料與結算

- `public/cultivation/quest-rules.js`：共用純規則、任務目錄與台灣日期。瀏覽器與伺服器共用同一份定義。
- `users/{uid}.questProgress`：各玩法累計與當日計數。問道、閉關、鬥法、團本與洞天在各自原有結算交易中記錄，不因領獎而加次數。
- `users/{uid}.storyProgressV1.seen`：已完成章節及完成時間，於首次觀看結束後保存；重播不重寫。觀看任務沿用這份完成紀錄。
- `users/{uid}.storyDongtianTutorialV1`：獨立洞天教程完成紀錄，`completed` 為真且 `skipped` 不為真僅供選用功能自身紀錄，不列為任務。舊版 `qiFiveDongtianTutorialV1` 必須有完成、已遊玩、已刪除三項標記才計入。
- `questStates/{uid}`：第 2 版使用固定 ID 的 `pathClaimed` 清單保存仙道已領獎任務，`pathIndex` 指向第一個未領任務；每日已領任務獨立保存。舊版數字指標依原 21 項目錄轉換，新增章節任務可補領，原有獎勵不會再次發放。此集合不得開放客戶端寫入。
- `questStates/{uid}.pathTicketAmounts`：依任務 ID 保存累計已發票券張數，與正常領獎或補領及票券入帳在同一筆交易內完成；補領僅發放設定獎勵減去已發量。`pathTicketsClaimed` 保留已領足的 ID；只有舊版 ID 清單時，以每項已發 1 張遷移。票券花掉或每日重置不清除已發量，讀取任務不會自動發券。
- `GET /api/quests` 與 `POST /api/quests/claim`：使用 A 專案登入 token，UID 取自驗證後的 token。伺服器依保存的玩家進度判斷資格與固定獎勵，忽略客戶端獎勵值。
- 領獎與任務狀態更新在同一筆 A 專案交易內完成；重試、重整、多分頁同時領取只入帳一次。跨日的舊日常請求會被拒絕。
- 日常事件沿用各玩法的既有信任模型；正式鬥法、團本與洞天以伺服器結算為準，問道與閉關沿用原有玩家結算。
- 介面在返回仙府、結算、範圍儲存、完成章節、完成洞天教程、切回瀏覽器、日期改變時同步。沒有持續輪詢 API。

後續任務請新增固定 ID，不可改用既有 ID 表示不同任務。既有任務追加獎勵時，需獨立記錄新增部分的領取狀態，不重置原有領獎紀錄。`LEGACY_PATH` 保留舊版遷移順序；新版使用已領 ID 判斷重複，不以目錄位置判斷。靜態檔修改後執行 `npm run build:module-versions`。

驗證：`npm test` 包含任務跨日、接續、防重複、身份驗證、獎勵入帳，以及原有玩法結算與問道流程。

仙道獨立進程畫面依原有修為里程碑分組；左側可切換境界階段，中間顯示階段徽章與已領數，右側瀏覽已領、待領及後續任務。API 額外提供 `pathRows`，後續任務只供預覽，領獎仍由原先 `path` 驗證，不變更境界、任務順序或獎勵。

仙道使用獨立 `page-path` 導覽頁（與排行相同的主頁切換），不再受任務彈窗尺寸限制；日常與每週維持原彈窗。階段徽章下方列出現行玩法解鎖：入門玩法、築基鬥法、渡劫五仙問鼎；未啟用的舊金丹／元嬰等系統不列為已解鎖。
