# 修行任務

仙府的「修行任務」分成仙道與日常兩個分頁。玩家可查看進度、獎勵、前往對應玩法，達標後手動領取。

## 仙道

一次只有一個目前任務；完成並領獎後顯示下一個，共 37 項：原有 21 項修行任務、隨修行階段穿插的 15 項觀看劇情任務，以及 1 項獨立洞天新手教程任務。原有任務涵蓋儲存範圍、問道、閉關、各境界、鬥法、洞天與團本；觀看任務涵蓋第一章、入門續篇、第二至第十三章與終章。

只有第一章會在新玩家完成資料設定後自動播放。其他章節皆由玩家按仙道任務的「觀看劇情」或仙府的「主線劇情」清單開啟，提升修為、領獎或結束戰鬥不會自動彈出後續劇情。章節仍依原有修為門檻解鎖。

首次看完並按「結束本章」成功儲存後，觀看任務才達成；只開啟、看到一半離開、管理員預覽未解鎖章節都不計完成。保存失敗時保留最後一句，可重試。已讀章節重播不會重複領取獎勵，已有的完成紀錄與提早觀看的章節也計入。第一章觀看任務給 30 靈石，其餘每章 50 靈石，均不加修為。

煉氣五層的任務順序為「引氣入體 → 觀看第二章 · 竹簡天尊 → 完成洞天新手教程 → 靜心一日」。第二章只播放夢境，觀看或重播都不會啟動洞天教學。獨立教程可按任務的「開始洞天教程」，或洞府的「查看洞天新手教程」開啟，門檻為 5 修為。

教程必須實際完成私人範例作答、結算、返回名冊與刪除，並在最後成功儲存才算完成。「稍後再學」不算完成；保存失敗會停留在最後一步供重試。舊帳號已完整學過的紀錄仍計入；過去跳過的紀錄需重新完整學完。教程任務獎勵為 50 靈石、不加修為，重播不重複領獎；私人範例仍不計入正式洞天／日常完成次數。

次數型任務採累計進度，會保留提早完成的修行成果。已有的出題範圍、修為、問道正確數、鬥法場次、閉關天數與團本首勝可直接達成對應目標。過去缺少完整累計資料的團本／洞天次數，從功能上線後的結算開始累積（既有團本首勝保留一次）。

## 日常

| 任務 | 條件 | 獎勵 |
| --- | --- | --- |
| 溫故知新 | 今日問道答對 3 題 | 40 靈石、1 修為 |
| 勤學不輟 | 今日問道答對 10 題 | 80 靈石、1 修為 |
| 靜心閉關 | 今日完成閉關，無須全對 | 30 靈石 |
| 論道切磋 | 今日完成正式鬥法 1 場，勝負皆計 | 80 靈石 |
| 洞天探幽 | 今日完成洞天答題並結算 1 次 | 60 靈石 |
| 同門協力 | 今日成功通關團本 1 次 | 100 靈石、1 修為、淬靈玄印 1 枚 |

日常進度與領獎資格依 `Asia/Taipei` 每日 00:00 重置；仙道進度不重置。當日未領獎勵不保留至次日。兩個問道任務分別領取，答對 10 題時可領兩項。鬥法及團本入口與領獎需達築基初期（10 修為）。練習鬥法與洞天教學範例不計正式活動；退出、配對或僅開啟玩法不計次。

## 資料與結算

- `public/cultivation/quest-rules.js`：共用純規則、任務目錄與台灣日期。瀏覽器與伺服器共用同一份定義。
- `users/{uid}.questProgress`：各玩法累計與當日計數。問道、閉關、鬥法、團本與洞天在各自原有結算交易中記錄，不因領獎而加次數。
- `users/{uid}.storyProgressV1.seen`：已完成章節及完成時間，於首次觀看結束後保存；重播不重寫。觀看任務沿用這份完成紀錄。
- `users/{uid}.storyDongtianTutorialV1`：獨立洞天教程完成紀錄，`completed` 為真且 `skipped` 不為真才計入。舊版 `qiFiveDongtianTutorialV1` 必須有完成、已遊玩、已刪除三項標記才計入。
- `questStates/{uid}`：第 2 版使用固定 ID 的 `pathClaimed` 清單保存仙道已領獎任務，`pathIndex` 指向第一個未領任務；每日已領任務獨立保存。舊版數字指標依原 21 項目錄轉換，新增章節任務可補領，原有獎勵不會再次發放。此集合不得開放客戶端寫入。
- `GET /api/quests` 與 `POST /api/quests/claim`：使用 A 專案登入 token，UID 取自驗證後的 token。伺服器依保存的玩家進度判斷資格與固定獎勵，忽略客戶端獎勵值。
- 領獎與任務狀態更新在同一筆 A 專案交易內完成；重試、重整、多分頁同時領取只入帳一次。跨日的舊日常請求會被拒絕。
- 日常事件沿用各玩法的既有信任模型；正式鬥法、團本與洞天以伺服器結算為準，問道與閉關沿用原有玩家結算。
- 介面在返回仙府、結算、範圍儲存、完成章節、完成洞天教程、切回瀏覽器、日期改變時同步。沒有持續輪詢 API。

後續任務請新增固定 ID，不可改用既有 ID 表示不同獎勵。`LEGACY_PATH` 保留舊版遷移順序；新版使用已領 ID 判斷重複，不以目錄位置判斷。靜態檔修改後執行 `npm run build:module-versions`。

驗證：`npm test` 包含任務跨日、接續、防重複、身份驗證、獎勵入帳，以及原有玩法結算與問道流程。
