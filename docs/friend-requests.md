# 好友邀請

玩家可在輸入好友代碼後送出邀請，也可點其他玩家頭像開啟資料卡，或使用鬥法右上角的加好友按鈕。
代碼輸入框右側的信封按鈕開啟邀請彈窗，可同意、拒絕，以及設定「不再接受新的好友邀請」。此設定不影響既有好友，舊邀請仍可回覆。

好友關係由 `/api/friends` 驗證主專案登入身分後建立，只有收件人能回覆。接受時在同一個交易更新雙方好友名單；瀏覽器不能直接寫入好友名單或邀請偏好。既有好友無須重新邀請。

邀請保留 7 天，每人最多 50 筆待處理邀請；每位寄件人每小時最多成功送出 20 次，重複邀請不重寫資料。拒絕後保留 24 小時的再次邀請冷卻，每人好友上限 100 位。過期資料在讀取時過濾、下次寫入時整理，沒有清理排程。

每位收件人的資料存於私人 `friendRequestInboxes/{uid}` 文件；寄件頻率存於私人 `friendRequestOutboxes/{uid}`。不新增資料表或集合掃描，不需要 D1 migration。

通知沿用 `/api/invitations/listen` 的既有 Render 連線；離線、通知過期或伺服器重啟不會刪掉已儲存的邀請。登入、開啟收件匣、收到通知以及回到前景時才讀取狀態；前景更新有 60 秒快取與請求合併，不設額外計時輪詢。

一般狀態讀取涉及自己的玩家文件及收件匣兩筆文件。UID 發送涉及四筆文件讀取、兩筆文件寫入；代碼發送另查好友代碼索引。接受涉及雙方玩家及雙方收件匣四筆文件讀取、三筆文件寫入，若有交叉邀請則多寫一筆對方收件匣。實際 D1 rows_read、rows_written 與 Worker 次數仍受索引、交易重試與請求合併影響，應以 Cloudflare 指標為準。
