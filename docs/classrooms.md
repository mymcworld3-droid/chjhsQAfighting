# 教師與班級

## 入口與使用方式

仙盟 → 班級。仙盟不再要求築基境界；原有的年級／學制設定提示保留。鬥法配對與接受鬥法邀請仍遵循原來的境界規則。

只有管理員可以建立班級。一般帳號需在「教師帳號申請」填寫教師稱呼、學校／任教單位與申請說明，經管理員核准後，再由管理員指派班級。已核准教師可管理獲分配的班級、派題及查看成績，不能自行建班或取得全站管理員權限。每帳號最多加入或管理 20 班，每班最多 100 位學生。

管理員在「仙盟 → 班級 → 教師帳號審核」查看待審核、已核准、已退回及已撤銷帳號，核准、退回或撤銷資格並填寫備註；教師可查看自己的申請狀態與備註。退回或撤銷後可重新申請，但仍須再經管理員審核。管理員可查看所有班級，於班級內「指派班級教師」將班級分配給已核准教師，或收回自己管理。

原先自行建立班級的非管理員帳號不會自動取得教師資格，需重新申請並獲核准。撤銷資格即停止後續教師資料讀取及操作，班級、學生作答與歷史成績保留，由管理員接手或重新指派教師。

1. 管理員輸入班級名稱、教師稱呼建立班級，指派已核准教師，再分享八碼加入碼。
2. 學生輸入加入碼、供老師辨識的姓名及選填座號。教師可查看名單、移出學生、更新加入碼、修改班名、封存及恢復班級。
3. 教師新增作業，設定科目、截止時間（選填）、1–30 題單選題、每題四個選項、正確答案、解析與固定知識點（選填）。可沿用現有 AI 出題服務產生草稿，再編輯審核。
4. 儲存草稿後預覽整份題組，勾選確認才發布。發布後題目與答案固定。草稿支援版本衝突檢查及刪除；每班最多保存 100 份作業。
5. 學生逐題作答並保存，重新開啟可續答。全部完成後繳交，伺服器計分；同一份作業只保留一次首次成績，重複請求不覆寫。截止及結束收件均由伺服器判定。
6. 繳交後可以查看答案與解析並完成錯題訂正；訂正與首次成績分開記錄，訂正完成後不會被重複請求改回未完成。
7. 教師查看完成狀態、首次成績、錯題訂正、各題正確率、本次作業的知識點表現，並匯出 UTF-8 CSV。未作答資料顯示空白或「—」，不當成零分。成績平均只計已繳交學生。

## 資料與權限

沿用 A 資料庫的通用文件儲存與主專案登入驗證，不新增資料庫服務、索引或環境變數。部署新程式即可建立以下伺服器專用集合：

| 集合 | 內容 |
|---|---|
| `classroomProfiles` | 每個帳號的班級索引 |
| `classroomTeacherAccounts` | 教師申請、審核狀態、版本與管理員審核紀錄 |
| `classrooms` | 班級擁有者、加入碼、名單、作業索引與狀態 |
| `classroomCodes` | 隨機加入碼到班級的對照 |
| `classroomAssignments` | 草稿／固定發布題組、截止時間、發布時名單 |
| `classroomSubmissions` | 個別學生逐題進度、首次成績及訂正 |

所有操作經 `POST /api/classrooms`。Token 必須通過主專案的撤銷檢查、audience、issuer 驗證。操作者取自登入驗證；teacherUid 只能作為管理員審核／指派的目標，不能宣告自己的權限。管理員資格從資料庫 `users.isAdmin` 讀取，教師資格僅從伺服器專用集合的核准紀錄判定，不信任可由前端修改的 isTeacher 欄位、班級擁有者欄位或請求內分數。管理操作於交易內重讀權限，敏感讀取在回傳前再次確認資格及班級歸屬；審核使用版本檢查避免舊申請覆蓋新決定。

教師僅可讀取獲指派班級的作業與成績，學生僅可讀取已發布題目及自己的作答；繳交前不下發答案與解析，也不下發同學名單、成績或加入碼。管理員的班級及教師帳號列表每頁 50 筆，支援載入更多。

一般 D1 瀏覽器讀寫端點不能存取以上集合，前端也不直接使用 Firestore 存取班級資料。如使用 Firestore 後端而非 D1，既有 A 專案規則也必須維持伺服器專用集合預設拒絕；不可添加公開的讀寫規則。

更新加入碼會立即撤銷舊碼；移除或退出班級同步更新雙方索引，並撤銷學生存取權。發布時名單、後加入且已保存作答的學生、現有學生合併列入報表；學生退出後，原教師仍可查看該作業歷史成績。每份作業最多保留 1,000 位歷史參與者。帳號切換會清空畫面與快取，過期的請求不再寫回畫面。

班級題組的成績獨立於遊戲戰力、修為與靈石；不發放可由自建班級反覆取得的遊戲獎勵，也不把教師自編題的分數宣稱為經難度校準的能力分數。

## 驗證

- `node --test tests/classroom.test.cjs`：權限隔離、題組固定、進度續答、交易競態、首次成績、訂正、截止、代碼輪替、歷史報表、CSV 及直接讀寫防護。
- `node scripts/check-classroom-ui.cjs`：需要 Playwright Chromium，使用本機測試資料與假登入，走過建班、AI 草稿、審核派題、學生加入與續答、繳交訂正、報表匯出、帳號切換及橫直式版面；不連線正式資料庫。
- `npm run build:module-versions && npm test`：更新資源版本並跑專案回歸。

## 教學管理增強

- **班級公告**：獲指派教師可發布最多 1,000 字的公告，保留最近 20 則，學生在班級內查看；封存班級不能發布新公告。公告寫入與刪除都在交易內驗證教師權限，不公開給班外使用者。
- **學習總覽**：教師可按需查看最近六份已發布／已結束作業的繳交、作答中、未開始人數，以及目前班內學生的繳交概況與首次平均分數。只統計仍在班學生；草稿排除；未繳交不計零分。教師點擊時才載入，避免正常進入班級時額外讀取大量作答資料。
- **截止與重新開放**：已發布或已結束作業可在成績頁修改截止時間，留空則取消時間限制；教師可明確重新開放已結束的作業，截止時間已過則必須先延長。題組和已繳交的首次成績不變，交易版本檢查防止其他視窗覆蓋。
- 增補測試涵蓋公告權限／封存限制、已逾期作業延期、重新開放後續答、成績不覆寫、總覽隱私與缺交資料呈現。


## 第一階段：教室介面重構（2026-11-20）

- 教師班級頁新增六個分頁：**總覽／作業／學生／成績／公告／設定**；學生僅顯示 **總覽／作業／公告／設定**，不提供班級名單、教師報表、加入碼或管理操作。
- 總覽顯示已知的班級人數、作業數量與最近公告，不在未取得提交紀錄時推估繳交率。成績分頁保留各份作業報表入口，學習總覽須教師主動點擊才會讀取多份學生作答紀錄。
- 作業分頁可依標題／科目搜尋及狀態篩選；學生分頁可搜尋姓名／座號。公告、加入碼、重新命名、教師指派與封存操作均移至清楚對應的分頁。
- 切換分頁不改動既有作業、成績與公告資料，重新整理班級與返回班級時保留選取的分頁。更換班級時重設分頁、搜尋條件與總覽快取，避免跨班級資料混用。
- 手機和平板採橫向可滑動的分頁、單欄卡片、響應式統計卡與可滾動的表格，提供鍵盤左右／Home／End 切換分頁。
- 本階段只調整介面，不更動管理員建班權限或教師洞天工作流；後者會在後續階段統一。保留原有續答、訂正、題組發布、CSV 匯出及伺服器權限限制。
- 測試包括獨立的教室畫面輸出單元測試，以及 Playwright 學生、教師、公告、派題與手機寬度的流程驗收。


## 第二階段：教師工作台（2026-11-20）

- 已核准教師及管理員進入「仙盟 → 班級」後顯示**教師工作台**，使用「總覽／我的教室／作業與待辦」三區，保留原班級內六分頁及學生一般入口。教師洞天可從工作台一鍵前往，沒有新增遊戲底部導覽按鈕。
- 工作台呈現管理班級數、學生人數、近期未發布草稿，以及三日內截止的作業。每個班級提供「進入教室／新增作業／查看成績」，跨班作業可以搜尋和篩選，草稿可直接進入既有編輯與發布流程。
- **數據範圍明確限定為每班最近六份作業**，每次最多載入 20 班；若管理員可管理的班級超過 20，透過「載入更多班級」分頁載入。這些資料用於工作提醒，不是整體歷史統計或真正的缺交人數。
- 學生的作答資料**不會因進入教師工作台而批次掃描**。老師按下單份作業的「查看繳交」，才會進行該班最多 100 位現有學生的作答狀態讀取，顯示已繳交、作答中、未開始數字及最多 12 位尚未繳交學生，並可進入完整成績報表。伺服器會在讀取後再確認最新教師權限及班級歸屬，撤銷教師資格後不得查看。
- 工作台沿用既有「管理員建班／教師審核」制度，沒有暗中開放一般教師自行建班（該功能排在班級管理優化階段）。管理員的建班表單保留；已核准教師仍能進入自己**作為學生**加入的其他班級，避免因教師入口切換而遺失原本權限。
- 對工作台介面提供空班級、載入失敗與不同角色的安全顯示，支援手機單欄卡片、搜尋篩選、鍵盤切換與完整桌面版。既有派題、洞天編輯、首次計分、訂正、匯出及伺服器權限規則保留。
- 教室瀏覽器 CI 已新增跨班級、快速派題、作答繳交、工作台繳交明細、學生角色隔離與 320px 手機寬度的整體驗收；新增工作台前端單元測試與伺服器權限、分頁、失效資格回歸。


## 第三階段：派題與編輯優化（2026-11-20）

- **單題編輯器**：改為「作業設定 → 題目清單 → 當前題目」，同時只顯示一題完整表單。題目可快速切換、上移、下移、複製、刪除，保留 30 題上限；手機版將題目清單變成橫向可捲動選擇列。
- **批次 AI 出題**：教師可一次產生 1／5／10 題；最多同時三個 AI 請求。逐批檢查 JSON、四個互異的非空選項、文字長度、正確答案與重複題目。無效或重複題目會略過，不補發無限制額外請求；仍以 30 題為上限。所有 AI 內容僅作草稿，必須教師逐題確認後預覽發布。
- **草稿自動儲存**：編輯輸入後會在完整內容符合格式時防抖儲存至既有的版本控管 API。題幹缺漏、選項重複或其他未完成欄位不會自動寫入，畫面內文字保留並提示；寫入序列化，伺服器回應只更新代碼與版本，避免覆寫教師在網路請求期間的輸入。儲存失敗會提示，不會強行覆蓋其他視窗資料。只儲存草稿，不自動發布。
- **重用既有作業**：已發布或草稿皆可複製到一個或多個教師可管理的教室，逐班建立完全獨立的新草稿；原作業題目、成績、訂正及提交紀錄不會連動，新草稿不帶入原本截止時間。多班複製逐班呈現成功與失敗；所有草稿依然需預覽審核才可發布。
- **權限與資料安全**：新增伺服器動作 copyAssignment，以交易驗證來源與目標班級教師資格、作業真實歸屬、目標未封存及上限，且不信任前端角色欄位。新作業使用獨立 ID、版本 1、不繼承提交資料。
- **驗收**：新增編輯器模組單元測試、後端跨班複製與撤權回歸，擴充 Playwright 批次生成、快速切題、排序、草稿自動儲存、多班複製及學生續答與訂正的驗收。


## 第四階段：班級與學生名單管理（2026-11-20）

- **教師自行建班**：帳號經管理員核准的教師可在教師工作台自行建立自己的班級，無須管理員逐班代建；建班後教師即為班級擁有者，教師名稱由伺服器採用已核准帳號資料，不接受前端自行指定管理員身分、任意教師身分或偽造教師名稱。管理員仍可建班並另行指派教師。單帳號維持最多 20 班的限制，審核撤銷後不允許繼續建班。
- **學生資料編輯**：在「學生」分頁以姓名／座號搜尋、依座號或姓名排序，可單筆編輯或透過安全 CSV 一次批次更新姓名與座號。學生身份以原本帳號的 uid 比對，任何資料修改不會建立新帳號、合併不同帳號、重計首次成績或重寫學生提交紀錄。教師修改過的姓名／座號不會被學生以原加入碼重新加入而覆蓋。
- **CSV 匯入與預覽**：先匯出 UTF-8 BOM 的 uid,name,seat 三欄名單，修改後重新匯入。解析支援正規 CSV 引號、逗號與換行，避免試算表公式注入；系統只辨認目前班內既有 uid，不依姓名或座號猜測身分，也不會把陌生 uid 自動加進班級。匯入前呈現待修改、無變更與錯誤清單；有錯誤時整批禁止套用，伺服器以交易原子更新。
- **安全批次管理**：可勾選學生並一次移出最多 20 位；顯示二次確認。學生名單新增、變更、移出維持 rosterVersion，所有教師批次修改都檢查版本以阻止其他視窗或教師同時操作造成覆寫。封存班級不可編輯或移出名單；學生不可查閱名單或執行教師專屬操作；移出學生的既有已發布作業歷史成績仍保留供教師報表查閱。
- **驗收**：新增 CSV 解析／CSV 注入防護／名單編輯介面單元測試，以及教師自行建班資格、角色撤銷、20 班上限、版本衝突、單筆及批次編輯、原始成績與移出歷史保存的後端測試，並補入 Playwright 實際建班、編輯名單、CSV 預覽匯入及批次移出流程。

## 第三階段補強：維持一個 API 請求只產生一題

- 教師操作「AI 產生 1／5／10 題」表示執行相同次數的單題 API 請求，不是要求一次 API 產生多題。現在固定以 questionCount=1 呼叫單題生成端點，每次收到單題 JSON 才處理下一次生成，讓後續請求能參考先前已接受題目的題幹並避重，並控制一次只有一個生成請求進行。所有生成仍須教師檢查後才會儲存草稿及預覽發布。
