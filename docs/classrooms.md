# 教師與班級

## 入口與使用方式

仙盟 → 班級。仙盟不再要求築基境界；原有的年級／學制設定提示保留。鬥法配對與接受鬥法邀請仍遵循原來的境界規則。

任何已登入帳號都可以使用「教師建班」，管理自己建立的班級；教師身分是班級內的擁有者權限，不會取得全站管理員或其他班級權限。每帳號最多加入或管理 20 班，每班最多 100 位學生。

1. 教師輸入班級名稱、教師稱呼，建立班級並分享八碼加入碼。
2. 學生輸入加入碼、供老師辨識的姓名及選填座號。教師可查看名單、移出學生、更新加入碼、修改班名、封存及恢復班級。
3. 教師新增作業，設定科目、截止時間（選填）、1–30 題單選題、每題四個選項、正確答案、解析與固定知識點（選填）。可沿用現有 AI 出題服務產生草稿，再編輯審核。
4. 儲存草稿後預覽整份題組，勾選確認才發布。發布後題目與答案固定。草稿支援版本衝突檢查及刪除；每班最多保存 100 份作業。
5. 學生逐題作答並保存，重新開啟可續答。全部完成後繳交，伺服器計分；同一份作業只保留一次首次成績，重複請求不覆寫。截止及結束收件均由伺服器判定。
6. 繳交後可以查看答案與解析並完成錯題訂正；訂正與首次成績分開記錄，訂正完成後不會被重複請求改回未完成。
7. 教師查看完成狀態、首次成績、錯題訂正、各題正確率、本次作業的知識點表現，並匯出 UTF-8 CSV。未作答資料顯示空白或「—」，不當成零分。成績平均只計已繳交學生。

## 資料與權限

沿用 A 資料庫的通用文件儲存與主專案登入驗證，不新增資料庫服務、索引或環境變數。部署新程式即可建立以下伺服器專用集合：

| 集合 | 內容 |
|---|---|
| `classroomProfiles` | 每個帳號的班級索引 |
| `classrooms` | 班級擁有者、加入碼、名單、作業索引與狀態 |
| `classroomCodes` | 隨機加入碼到班級的對照 |
| `classroomAssignments` | 草稿／固定發布題組、截止時間、發布時名單 |
| `classroomSubmissions` | 個別學生逐題進度、首次成績及訂正 |

所有操作經 `POST /api/classrooms`。Token 必須通過主專案的撤銷檢查、audience、issuer 驗證；不採用請求內的 uid、teacherUid、ownerUid 或分數。教師僅可讀取自己班級的作業與成績，學生僅可讀取已發布題目及自己的作答；繳交前不下發答案與解析，也不下發同學名單、成績或加入碼。

一般 D1 瀏覽器讀寫端點不能存取以上集合，前端也不直接使用 Firestore 存取班級資料。如使用 Firestore 後端而非 D1，既有 A 專案規則也必須維持伺服器專用集合預設拒絕；不可添加公開的讀寫規則。

更新加入碼會立即撤銷舊碼；移除或退出班級同步更新雙方索引，並撤銷學生存取權。發布時名單、後加入且已保存作答的學生、現有學生合併列入報表；學生退出後，原教師仍可查看該作業歷史成績。每份作業最多保留 1,000 位歷史參與者。帳號切換會清空畫面與快取，過期的請求不再寫回畫面。

班級題組的成績獨立於遊戲戰力、修為與靈石；不發放可由自建班級反覆取得的遊戲獎勵，也不把教師自編題的分數宣稱為經難度校準的能力分數。

## 驗證

- `node --test tests/classroom.test.cjs`：權限隔離、題組固定、進度續答、交易競態、首次成績、訂正、截止、代碼輪替、歷史報表、CSV 及直接讀寫防護。
- `node scripts/check-classroom-ui.cjs`：需要 Playwright Chromium，使用本機測試資料與假登入，走過建班、AI 草稿、審核派題、學生加入與續答、繳交訂正、報表匯出、帳號切換及橫直式版面；不連線正式資料庫。
- `npm run build:module-versions && npm test`：更新資源版本並跑專案回歸。
